# A declared synthetic book shares cash across return and lease methods

SyntheticReturnLeaseBook/1 is a new conditional owner with one USD legal book,
one dated period, 25 debit-positive accounts and one event/flow history. It
retains return component, lots, tax memories and fiscal history; lease rights
are an additional separate collection. Its opening is expressly supplied,
not inferred by merging two owners. Original numeric component templates are
linked in provenance, and original source pointers remain template lineage.
They do not authenticate this new owner or dates.

The opening specifies cash 500, return inventory 60, recovery asset16, refund
liability40, ROU120 and lease liability150, plus the listed surrounding
accounts. Original equity is expressly20. No validation or execution step
calculates an equity/cash plug. Debit-positive opening equity is a synthetic
test amount; it is not a statement about a real company.

Return settlement and whole-lot sale reuse the checked typed prerequisites,
monetary expressions and memory operations. The memory schema is explicitly
extended to retain lease fields and all25 balances. No native opening is
projected into a smaller registry. Lease reduction/payment/depreciation reuse
the original component kernel and retain its annual timing, traced allocation
and cash-classification assumptions. The fixed-source SharedLeaseBook wrapper
is not relabeled or called on the new owner.

Selected lease postings map identically by name to cash, ROU, lease liability,
finance expense, depreciation and other gains in the new registry. Those six
meanings are explicit successor definitions. No corporate-return cost account
mapping is inferred. Return and lease modules share cash, the trial balance,
date and event/flow history; each changes only its own component memory.

Each proposal binds the full before-state, event, current implementation and
protected kernel bundle. Apply recomputes every field before returning a
new in-memory state. Ordered prefix execution stops on the first refusal and
preserves the completed prefix. It does not write a database. All source,
accounting, method-eligibility and physical durability flags remain false.
Tax memories are preserved; tax close and complete financial reports are not
implemented for this successor.
