# Remaining native obligations after typed templates

| Native condition | Existing support | Next action |
|---|---|---|
| Exact state/schema/roles/cost/migration premise | Native structural validation and earlier selected-opening machinery | Preserve separately; no replacement claim |
| Cursor before period end, sum claims=receivables, sale seen, remaining nonnegative, issue before book | Static BookStateInvariant/1, totals and seen collections | Author a term-compatible scalar claim declaration without legacy current-due overdue predicate |
| Nonempty terms, current ID/date equal latest | Checked group template | Retain unchanged |
| Strict effective dates and predecessor chain | Match and exclusive greatest plus typed term row captures | Author explicit term-row template and corruptions |
| Issue <= effective <= book, effective <= due | Guarded date predicates and captures | Include in term-row template |
| Term event seen | Existing collection references; projection bridge missing | Add generic projected collection adapter |
| Unique assessment dates | Match by date in same parent | Add explicit unique selection query to row template |
| Historical applicability, overdue, issue/book/cursor dates | Checked assessment row template | Retain; add remaining nonnegative condition |
| Origin imported/recorded and event identity | Guarded predicates plus conditionally filtered seen references | Add explicit origin predicates and typed-equality projected collection filter |
| Assessed flag/cardinality, latest/summary, empty sentinel | Checked group template | Retain unchanged |

Generic template validation contains no financial field names. A financial
declaration is now feasible for most relations; the source-membership bridge
remains the smallest missing primitive. The native date sort is a reference
implementation choice: unique-date plus greatest-predecessor selection can
express the same order relations without silently changing insertion order.
