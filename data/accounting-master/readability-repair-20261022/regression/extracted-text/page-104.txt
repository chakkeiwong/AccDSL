7.9
Errors are part of the interface
The compiler and runtime return typed diagnostics with a source span, affected entity and
period, dependency chain and suggested local action. The principal diagnostic categories have
distinct recovery paths:
Diagnostic
Meaning and next action
TypeMismatch, ContextMismatch
Resolve incompatible units, periods, entities
or measurement bases; do not coerce
implicitly.
MissingEvidence
Supply a source or label a model input as an
assumption.
InfeasibleHistory
Inspect the conflicting evidence and model
constraints; preserve the rejected candidate.
RuleConflict, UnknownApplicability
Resolve rule scope or preserve a justified
conditional partition.
UnsupportedTreatment
Add a reviewed capability or leave the
affected output incomplete.
UnbalancedBatch
Reject the atomic update and diagnose the
posting rule.
SolverIncomplete, NumericalFailure
Preserve the target and inputs; repair or
change the computational method.
InsufficientSimulationState
Add declared conditional assumptions or
request a family of results.
Warnings can describe low extraction confidence or an approximate economic model, but they
do not replace these errors. A required unknown input prevents a concrete unconditional result.
The analyst can add a declared conditional assumption, request bounds, or leave that output
incomplete. Every path has a different, explicit result type; there is no generic fallback to zero.
