8.3
Share common structure without merging worlds
If a thousand histories differ only in one loan’s reset clause, their source reports, asset register
and most events can be shared. Each alternative stores its clause condition and local differences.
This reduces storage without identifying the alternatives economically.
A common event prefix can be executed once when every history has the same relevant state
and rule up to a boundary. Execution separates at the first differing reset or decision. Persistent
data structures retain ancestors and changed fields for explanation and replay.
Sharing must not allow mutation of one branch to alter another. Refinancing in one history
cannot rewrite the common original loan.
Immutable contract versions and branch-local
successor records prevent that failure. Cache identities must include all relevant inputs and rule
versions, not merely a displayed company name.
8.4
Elimination must preserve consequences
If a query uses variables x and the full family is C(x, z), exact elimination of z means
CQ(x) ⇐⇒∃zC(x, z).
(8.1)
Dropping every constraint containing z is generally not this projection. Constraints x = z + 1
and 0 ≤z ≤2 imply 1 ≤x ≤3. Removing both constraints leaves x unrestricted. Correct
elimination retains the implied interval.
Projection can create dense relationships among remaining variables. A small original repre-
sentation does not guarantee a small projected one. A dependency slice must include outputs,
event guards, feasible actions and observation rules over the horizon. A variable absent from
today’s report can affect tomorrow’s signal or covenant.
An asset identifier irrelevant to interest expense may matter to collateral eligibility. A customer
identifier irrelevant to total receivables may matter to concentration. Query-driven elimination
therefore follows economic dependencies rather than simply selecting columns present in the
requested output.
8.5
Split where behavior changes
If every member of a region follows the same affine transition, propagate it symbolically. When
a guard changes the event rule, partition the region or retain a piecewise expression. For cash
90 −2α and requirement 89.4, the split is α ≤0.3 versus α > 0.3. The equality belongs to
compliance under the inclusive rule.
If breach has no effect on the requested output, its consequences may be deferred while the
condition is retained.
If it changes funding eligibility, it matters immediately.
Repeated
guards can still create exponentially many distinct behaviors. Guard-based execution avoids
unnecessary expansion; it does not prove universal tractability.
