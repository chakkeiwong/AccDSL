A.54.14
Compose methods, state controls, and event intent in one authored
program
The preceding examples established four separate boundaries: a method can be written in
complete text, a registry can retain its source and identity, a state invariant can reject a bad
book, and a selected event contract can retain the caller’s full intent. A usable program must
express those choices together. Otherwise a typed fixture may pass while the proposed language
has no way to write the same program or to show which semantic owner supplied a missing
field.
AuthoredCompanyText/1 closes this composition boundary with a bounded source format. The
program imports the opening book, report schemas, statement mapping and memory definition
by exact SHA-256 identities. It selects one BookStateInvariant/1 resource explicitly. These
imports are facts and checked rule resources; they do not silently generate methods or claim
that a small synthetic state is a complete disclosure history.
Each registry entry contains the complete CompanyMethodAuthoring/1 source block. The entry
records its lowered method digest, source digest, transition profile, input declarations, account
classes, clock and separate entry-schema resources. A registry version therefore cannot hide a
transition change. The method header supplies the transition profile, while the program author
chooses the registry and method for each event. Entry schemas remain distinct from the shared
report schemas because combining them would change the identity of a report request.
For the selected receivable contract, the same program also declares the native implementation
identity, role-to-account map, unit-cost pointer and policy. Every event carries both its projected
method inputs and its complete original intent. The latter retains the customer, claim and
interval assertions that a specialized method may remove from its calculation inputs. The
runtime then checks the selected native lifecycle on the current book and requires the authored
projected request to equal the declared projection of that full request. An edited half-collection
method therefore remains executable under the guarded target, where it changes the resulting
