# Function-extension review

The compiler lowers typed pure-function declarations to the pinned existing
expression evaluator. It changes no arithmetic, policy generator or company
accounting engine. The function request and lowered legacy graph retain distinct
identities. New source evidence is required for temporal admission.

| Decision | Primary criterion | Veto status | Main uncertainty | Next action | Not concluded |
|---|---|---|---|---|---|
| Retain optional typed functions | Exact manually inlined values and complete policy/path/accounting comparisons | Static, unknown, type/context, recursion and resource tests pass | General language and behavior remain incomplete | Integrate checked semantics, then matched text authoring | Whole DSL or production readiness |
| Preserve demand-driven semantics | Unused arguments and unselected branches follow the old evaluator | Wrong types/references still refuse, selected zero division invalid | This is an explicit scoped language choice | State it in the manuscript and parser contract | Universal function-call semantics |
| Preserve bounded expansion | Nodes, scope visits, call depth, expanded depth and serialized size bounded | Boundary checks pass after correcting a fixture count | Limits are convenience choices without scalability evidence | Keep refusals visible | Arbitrary-size execution |

A new alias-only test initially miscounted template validation visits. The
compiler correctly refused the over-budget request; the test and written bound
were corrected, as recorded in boundary-repair.md. No implementation change was
needed. This failure invalidated that fixture expectation, not the candidate or
the research direction. No continuation veto remains.

Post-run challenge: output equality on this collection example does not prove
equivalence of every possible function program. Adverse tests and lowering reuse
support the stated bounded reference behavior; they do not replace a formal
semantics proof. The expression baseline itself remains a checked reference.
Unknown information does not become known because a function compiles. The
weakest broader evidence remains real behavior and full company-method coverage.
The source comparator's sample fits play no role in this engineering decision.

No statistical ranking was attempted. Stochastic evidence classifications,
training budgets, seeds and GPU execution do not apply to these exact checks.
