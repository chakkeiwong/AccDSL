# Explicit event composition through complete programs

26 October 2026. MC05/15/18/20/24/25/33/34. Question, comparator,
diagnostic roles and limits are in the active phase plan. The skeptical audit
passes with the following limits recorded before implementation.

The input declares opening book, schemas, report mapping, typed memory,
authored invariant, an explicit rule pair per operation (eligibility plus
parameter/ordered construction), full-intent event commands, reports and carry.
Each assessment command carries its full claim-key order. Rules and invariant
have exact hashes; program identity additionally binds each event's input order.
No complete native method, after-state or expected outcome is input to execution.

Opening admission remains a separately performed prerequisite. The verification
harness calls the original native opening/program validation before disabling
all native lifecycle functions during candidate execution. The candidate checks
its own structure, typed opening and authored invariant, but explicitly reports
that the full native opening contract was not evaluated by it. This is a finite
composition test, not a general opening-contract replacement or admission token.

At each command, validate identity uniqueness, typed state and the selected
authored state invariant. Event eligibility evaluates before construction; an
eligible event is constructed from the current state and submitted to the
unchanged typed transition. Reports/carry reuse their original owners. Carry
requires the explicitly selected preserve-all-memory policy. Successful output
must pass the typed book and authored invariant again before current/opening
advance. On any failure, retain the successful prefix, unchanged current/opening,
the failed command index and complete unexecuted suffix. No durable mutation.

The primary comparison preserves every complete native command request/result,
every before/after state identity, and complete reports/current. The candidate
adds explicit eligibility, construction and invariant traces; the native adds
its native observation/implementation fields. Those wrappers are saved and
classified separately rather than stripped and mislabeled whole-result identity.
Carry results include the complete archive and next opening. Native observation
is compared separately by applying the saved observer to candidate state.

Adverse cases: original 18 refusals; unknown/unsupported/invalid precedence;
invalid later gate definition before execution; duplicate command identity;
changed state after a valid typed transition failing the selected invariant;
wrong carry policy; stale rule/invariant/program/input-order identities.
Runtime/counts are explanatory only. Any substantive payload disagreement,
mutated protected file or native execution callback is a promotion veto. An
invalid comparator is a continuation veto until repaired. No agents, installs,
GPU, commits, external actions, default change or E3.
