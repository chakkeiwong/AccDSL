# Resumed portable-authoring audit

Resumed after reload; source package retains its 20261023 identity. Governing
plan: docs/plans/accounting-company-portable-authoring-20261023.md.

Audit passes for a bounded reference implementation. The comparator is the
protected recorded bytes and their exact trusted replay, not rebuilt fixture
numbers. The portable encoder and reachable-closure validator are reused.
The richer schema exposes dependencies but explicitly imports legacy drafts;
it does not establish full normalized language semantics. JSON Boolean versus
integer identity, non-ASCII encoding, duplicate keys and forged-but-rehashed
results require adverse checks. Equal paths with different member names are
valid authored choices and do not gain weights or probabilities.

Primary pass criterion is preserved source bytes, typed closure and exact
trusted execution including partial outcomes. Structural consistency alone is
explanatory evidence, not semantic acceptance. Changed predecessor hashes or
missing indispensable comparator bytes veto dependent execution. A rejected
candidate triggers repair, not abandonment. No forecasting, accounting-source
admission, historical execution, durable publication or whole-language
completion follows. CPU-only deterministic checks need no statistical ranking.

Defaults and provenance: existing portable JSON and draft JSON encoders are
compatibility requirements; caller-supplied local methods are a declared trust
boundary; six scenarios are the protected example rather than a population;
checkpoint granularity is the already checked complete-member boundary. First
diagnostics check Unicode identity, closure loss and a forged cash result.

Subrecords extracted from a saved JSON file must carry their parent import and
JSON pointer. Their canonical extracted bytes must not be described as original
standalone source files. Exact original files remain separately preserved.
No supplied module path or source text is executed. Preserve failed evidence
before repair; successful verification receives a manifest and read-only replay.

Identity clarification before execution: literal and escaped Unicode encodings
cannot have the same raw import record while preserving different original
bytes. They share a DraftContent record, which binds canonical decoded legacy
content, profile and decoder. Their DraftImport records remain distinct and
point to that shared content. Full exchange identities also differ when source
bytes differ. This repairs an ambiguous sentence in the original plan rather
than silently discarding raw provenance or asserting incompatible hash goals.
