The independent financial checker reads preserved economic inputs, not authored
expected statement fields, to calculate schedules and consequences. It also
compares those calculations with the old expected values. It derives time
selection and input rejection from supplied fields, verifies closure and exact
submission bytes, and computes allowed transaction changes. Five deliberately
wrong rate/quantity/world/time/unknown variants challenge those checks.

The first unfinished draft had material errors: three units stood for an
eight-unit source package; the historical-to-forecast state chain was missing;
unknown final closing balances could be zero; replay used an unexplained later
head; import and saved work had no metadata transaction; valid transaction
conflicts were labeled structurally invalid. These were repaired before the
specification was accepted as a provisional documentary example. Source
supersession now changes interpretation/selection, preserving both faithful
literal extractions. The new debt text grammar is explicitly bounded and
distinct from the old Core0 implementation.

No stochastic comparison was run. The strongest alternative explanation is
that an authored fixed profile can hide missing general operations despite
passing its own examples. The independently calculated finances and adverse
mutations reduce that risk within Northstar, while R02, whole-candidate review
and later runtime conformance remain necessary. A counterexample to chronology,
dependency closure or same-history arithmetic would reopen the affected exchange.
The result repairs the specification; it does not reject the broader direction.
