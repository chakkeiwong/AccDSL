# Independent boundary diagnostic of the dependency evaluator

26 October2026. MC05/17/19/20/24/25/28/33/34; W05/06/07/08/16.
New dependency code is being written in the shared worktree. This diagnostic
uses a copied, hashed snapshot under scope-inspection and does not overwrite
the live evaluator or other work. It is a bounded source/control correctness
check, not a standards-admission test or a performance experiment.

Question: does the evaluator preserve unresolved alternatives and distinct
control dates, particularly when control existed before conversion or is lost?
Comparator: the inspected AASB10 §§7–8,20,25 and B47–B53, plus the explicit
local requirement that unknown remains unknown. Facts in cases are labelled
synthetic; the evaluator is not asked to determine their truth.

Primary pass: legal date/record validation and coherent dependencies at each
boundary. Unknown prior control must not eliminate the continued-control
possibility. Prior control followed by no control must not describe continued
control at conversion. Canonical date checks must reject basic/week-date forms
if the profile relies on lexical equality of YYYY-MM-DD strings.
Veto: a misleading exclusive route/timing statement or accepted malformed
context; repair trigger: targeted schema/routing correction. Counts and elapsed
time are explanatory. Compile failure invalidates only the snapshot diagnostic,
not the program direction. No journals, values or accounting admission follow.

Default audit: synthetic yes/no/unknown fields isolate routing logic, not real
rights. The smallest comparison changes one assessment/date at a time. A failed
case demonstrates a local missing condition only. Save source hash, exact
command, inputs, outputs and decision; at most30seconds CPU, no GPU/installs,
no successful writer reruns. Other shared work remains untouched.
