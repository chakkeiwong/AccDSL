This document specifies a system that translates company disclosures into traceable evidence,
represents several compatible economic and accounting histories, and simulates their future
journals and financial statements under explicit economic scenarios.
The proposed data contracts, methods and acceptance cases specify the intended implementation.
Current source and domain limitations remain explicit; this candidate is not a completed product
or a claim of full proposal readiness. Proposed libraries can be replaced while preserving those
contracts. Sector rule packages require their own accounting review before they can be described
as compliant with a reporting standard.
Research materials, source qualifications and review records accompany this document in
docs/design/research and docs/design/review.

17.30.2
Resume from the current book and report from the period opening
Execution and reporting need different dates here. The original period opening supplies the
starting cash and empty current-period flow history for a cumulative report. The current
book supplies the balances, last event date, used identities and contract memory for the next
instruction. Replacing one with the other would either forget accepted events or misstate the
reporting interval.
The present declared-program runner validates a fiscal opening at the period start with no flows.
It therefore refuses a midperiod current book as its opening. The selected continuation uses the
same typed event engine directly for one instruction, retains the actual prefix unchanged, and
reports the resulting book against the original period opening. This is a checked single-step
interface. A general program-resumption interface still needs explicit bindings for both books,
the verified prefix and the remaining commands; it cannot be implemented by resetting a date
or discarding prior flows.
17.31
Resuming selected payments without losing their history
A selected same-period runner now extends the checked coupon prefix through several supplied
instructions. Its plan retains the original period opening for reports and the current book
for execution. It also identifies the original source, selected method registry, verified prefix,
complete future instruction list and resource limits. A checkpoint’s cursor counts only accepted
new instructions. The earlier coupon refusal remains in its archive; it is not replaced by the
outcome of a later payment.
For a successful three-instruction suffix, processing one event per call, two per call or the whole
suffix produces the same terminal checkpoint. The complete accepted journals, dated flows,
current book and cumulative report agree with independent arithmetic and uninterrupted
execution. This comparison also covers a later unaffordable payment, duplicate identity and
backwards date. In each case, execution retains the accepted prefix and leaves the refused
instruction first in the remaining list.30

Resource limits apply to the entire selected suffix, not afresh to each chunk. The inherited
command ceiling is 64 and the default trace allowance is 8 MiB. A deliberately smaller allowance
exposes the boundary exactly: 82,883 bytes fit the first accepted trace row, but not the second.
An allowance of 82,882 bytes accepts no row. The runner retains the next command and
reports the unchanged accepted state in both cases. Splitting execution into additional calls
does not enlarge the allowance. These limits govern this diagnostic implementation; they
neither determine the financial shortfall nor prove that a larger economically feasible schedule
is impossible.
The checkpoint’s hash is necessary for identifying the supplied record but is insufficient for
validating it. The selected interface recomputes the bounded accepted prefix from the identified
source, registry and instruction list, then compares the complete checkpoint. This detects
altered request metadata even when a narrower financial comparison would still find the same
balances. It also detects a changed opening, skipped cursor, missing trace, erased refusal,
modified report or enlarged plan budget. Recomputed validation does not append a second
accepted event or duplicate a cash flow.
This evidence establishes a selected same-period partial-coupon interface. It does not migrate
the general program runner, support every method or reporting-period transition, or establish
durable exactly-once commits under concurrent writers. Repeated prefix computation is also
a cost, not a scalability result. The distinction between original opening, accepted current
book and remaining instructions nevertheless supplies a concrete starting point for broader
resumption contracts without erasing the company’s earlier history.
