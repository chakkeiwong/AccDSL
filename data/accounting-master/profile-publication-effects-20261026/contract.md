# PublicationEffects/1 — retained-profile descriptor

This read-only design helper describes an invocation under one exact retained
profile/schema lock. It consumes the complete documentary request, result,
receipt and declared before/after world. It neither executes a financial method
nor authorizes publication. The input source packet and exact native references
remain attached to the descriptor; changed domain contents remain recoverable.

Four separate effects are recorded: publication of result/index records;
component-head changes; legal-account-head changes; and appended journals with
their native scope. A group worksheet journal is not a legal-book journal.
An assessment or report can publish records while changing no financial state.
A component method can change memory without a journal. Empty journal therefore
does not establish no effect, and a true native additional_commit does not
establish a financial posting.

| Profile | Exact identity fields | Meaning of native additional_commit |
|---|---|---|
| InsuranceComponents/1 | client_id, request_id | New result/report publication |
| GroupComponents/1 | workspace_key, request_id | New component/result/report publication; missing on rejected null payload |
| BankAssessment/1 | workspace_key, request_id | New query publication |
| InsuranceAssessment/1 | client_id, request_id | Financial commitment, always false for these query publications |

The descriptor's identity is an explicit ordered pair plus the exact profile
reference. The legacy insurance slash key is retained as opaque source data,
never split or treated as an injective pair encoding. Its separate successor
index repair governs any future metadata migration. Profile names or equal
owner strings do not establish economic equivalence across the four locks.

A known publication requires the new immutable decision, result/receipt binding,
published dependency closure and permitted ownership changes. Previous published
records and decisions cannot disappear or be overwritten. Journal history is
append-only; each added journal must equal its bound native result's journal.
All undeclared world fields refuse rather than being silently omitted.
Insurance state changes retain roles and owner identifiers and advance one
generation. Group changes affect only the isolated component head, preserving
legal books. Assessment fields, accounts, journals and unrelated owners remain
unchanged. A native report changes no financial head or journal.

Replay describes this invocation, not the historical effect in its old receipt.
It returns the same result and receipt, preserves original diagnostics and any
native statuses/coverage, and changes no world. Refusals also change no world and
return no success receipt. The descriptor validates observable bindings and
effects, not every native input's financial or accounting validity.

A TransportObservation with unknown acknowledgement has unknown publication
and null effects. The descriptor deliberately does not infer a visible outcome
from a hidden committed/uncommitted test world. Both possible worlds remain
available separately to the conformance verifier; a later retry has its own
known invocation descriptor. Unknown is never normalized to false or to an
invented OperationResult.

All descriptors say specification_example and no execution admission. The
complete source/world references make this a comparison format, not a new
transaction protocol or a financial-method migration. Actual store atomicity,
cross-profile execution, source eligibility and financial correctness retain
their own requirements.

Submission binding respects each native encoding: InsuranceComponents hashes
the request body; the other three hash the complete immutable request record.
Group and bank submissions identify their decoder and wire blob instead of
containing a request_ref field. Retained blob bytes are checked separately by
the verifier; the descriptor checks their declared digest against canonical
request bytes.

A group component may read a later immutable legal-book snapshot in its new
state. Its proposal must bind that successor, while legal_heads in the world
remain unchanged. Treating a changed read reference as a legal posting would
misclassify the retained inventory-release example.
