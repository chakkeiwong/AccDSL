# Full-intent eligibility needs ordered stages

26 October 2026. MC05/15/17/18/20/24/25/33/34; S2/S3/S4. Ten source-anchored
rule groups are mapped in guard-map.json. Six exact examples across both charts
show that a flat MethodRequirements/3 conjunction is wrong relative to the
retained lifecycle's public refusal classification. Four additional probes
confirm sealed-window-before-claim and cursor-before-window ordering. All 83
protected predecessor files remain unchanged.

When a customer's identity is unknown, approval is false and the selected claim
is absent, the native lifecycle first returns unresolved for the unknown input.
A flat conjunction gives invalid for the missing claim. With known customer,
false approval and an absent claim, native returns unsupported before lookup,
while the flat conjunction returns invalid. Its invalid/unsupported/unresolved
precedence is a valid general requirement aggregator, but it computes a
different public decision from this sequential event contract.

Most individual predicates already exist: typed equality, date ordering,
Boolean approval and knownness. Missing binding semantics concern computed
map membership and typed selected-row lookup. The assessment interval also
needs an explicit calendar-day adjacency relation; rational subtraction is
not a date operation. Its exact meaning can be stated as end-exclusive ordinal
minus assessment-date ordinal equals one, after typed date validation. This
avoids constructing a predecessor outside the valid date range.
