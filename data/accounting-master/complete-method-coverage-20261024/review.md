# What remains before one return method is fully declarative

24 October 2026. The common requirement core, authoring frontend and exact input
binder address selected scalar prerequisites. They do not govern the complete
return method. The six inspected boundary files contain source admission,
structural validation, collection/order checks, component and book invariants,
event-specific preconditions, transitions, trusted proposal replay and reporting.
Each has a separate role; an additional true caller finding cannot substitute
for any missing calculation.

The inventory preserves every If/For/Raise/Assert/except anchor and selected
validation/requirement call in those six files, including its exact source text,
line, enclosing function, guards and loops. A second AST walk independently
checks anchor enumeration. This is source accounting, not a proof that code
contains every scientifically or financially necessary condition. Imported
surrounding-method internals remain an external retained dependency.

All 109 prior adverse cases have explicit dispositions. All 496 original check
records are preserved. They are historical evidence, not freshly executed full
method tests. Branch-level test attribution remains pending; counts cannot close
that gap. The finite native implementation remains the comparator.

An important timing point is already intentional: native initialization rejects
invalid authoring but can retain unresolved tax findings. Earlier non-tax events
can succeed, then tax stops at its own missing premise. Treating all global
unknowns as a universal execution veto would erase valid partial progress. The
current common evaluator has no execution permission precisely because this
event-specific scheduling decision is not yet represented.

## Existing expression machinery

Core 0 already has typed expression nodes and evaluate_expression in
scripts/core0_ir_v1.py. Its supplied-symbol arithmetic includes products, but
unknown references become symbolic placeholders, call returns its first operand,
and observation lookup selects a domain lower value within its validated finite
profile. Those semantics are not the requirement evaluator's explicit
known/unknown/context/admission contract. Reuse it as a checked exact-arithmetic
comparator for fully known operands; do not silently import its observation or
symbol behavior as generalized method admission. Earlier bounded searches had
not inspected this implementation; this audit records that limitation.

scripts/reconstruction_v1.py translates expressions to Z3 and depends on a
separate reconstruction/uncertainty contract. It is not a drop-in replacement
for finite caller-value requirement assessment. No solver migration follows.

## Selected next repair

The return refund equation requires units multiplied by currency per unit;
deferred balances require a currency amount multiplied by a rate. A plain
untyped multiplication would silently discard dimensional meaning. The smallest
next repair is an explicit dimension-aware product fragment with a versioned
type convention and lossless mapping from the protected v1 context types.
Compare known products with exact Fraction arithmetic and inspected Core 0,
but preserve unknown and context rules from requirements. Guarded predicates
and collection/state conditions follow as separate planned work.
