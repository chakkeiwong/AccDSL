# Chapter 5: shared semantics and replaceable tools

Fresh ordered reading covers physical pages80–83. The chapter turns the
literature's integration problem into one typed representation that several
authoring methods can produce. The diagram is legible and follows the already
motivated route from source evidence to histories,events,journals and results.
The60/40 borrowing assumption immediately demonstrates the difference between
creating a model and inventing a reported disclosure.

The alternatives table has a genuine comparison role. Typed Python is capable
of implementing the product;the textual DSL must justify its additional cost.
IR,validators and a reference API come first,with shared conformance cases for
both frontends. This preserves the prior chapter's conditional language choice.
The component table then serves as an implementation reference,with inspected
interfaces,candidate roles and license metadata kept separate from completed
integration or performance claims.

The conclusion identifies what reuse cannot decide implicitly. Contract adapters
return events and cash-flow information;valuation adapters return dated
measurements;solvers return scoped feasibility or bounds. Accounting recognition,
posting,temporal evidence and the distinction between sets and distributions
remain core responsibilities. That boundary prepares the mathematical chapter.

No confirmed new readability or semantic-boundary defect was observed. The
tables are dense but purposeful reference comparisons following the argument,
not substitutes for teaching a mathematical mechanism. Component execution,
deployment suitability and independent/human acceptance remain unestablished
by this author review.
