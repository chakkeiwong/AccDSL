# Revised-source actor messages: evidence contract

27 October 2026. MC03/04/05/08/10/12/13/18/24/25/26/28/33/34.
Plan: docs/plans/accounting-revised-source-actor-messages-20261027.md.

Question: do explicitly declared dated observations support one common finite
pay/draw rule across supplied source-history and economic-world alternatives?
Candidate: bind each financial row to one complete declared world, then attach
messages from each date's selected sources. Baselines: protected same-head
joint-stage policy rows/populations, independent direct row construction and
the retained reachable-policy oracle extended to the prospective total domain.

Skeptical audit passes with one scope clarification: the retained world binder
requires the corrected head to match the world and cover both selected heads.
It cannot express two conflicting receipt worlds for the same corrected head.
Multiple-world comparisons therefore explicitly pool independently admissible
source/world contexts. They are supplied alternatives with the same actor,
decision dates and action meanings, not a claim that both reports are true or
that the context identity is observed. A general uncertain interpretation of
one corrected report remains separate work. No source identity is a message.

Declaration RevisedSourceActorMessages/1 has exactly profile, contexts (ordered
external identities of family/world/mapping triples), mode, max_policy_keys and
provenance. Mode is numeric or numeric_and_reported_receipt. Provenance is
supplied_synthetic_observation_assumption. Each context contains a checked joint
source family, a SuppliedReceiptCorrectionWorld/1 declaration and a retained
ProspectiveActorObservationMap/1. No changes to actor, dates, rights or observation
semantics are inferred from a hash. Numeric tokens use the protected original
mapping; supplemented tokens pair that token with the currently selected
financial assertion's receipt value. This is a report, not actual future cash.

Before outcomes are filtered, derive the union domain from each original
financial head pair, observation head pair and supplied whole-world rows. An
impossible source pair can add unused keys conservatively; it cannot add a
selected economic history. First keys use only first messages; second keys
retain first message, first action and current message. Equal visible keys share
one action across all contexts. Key limit is the inherited reviewed bound 12;
overflow keeps exact required count and no candidate population. Never enlarge
the bound or collapse tokens to obtain an answer. Missing/unresolved worlds keep
their source supports/remainder and block full-family feasibility; any assessed
subset is explicitly only a restriction from the resolved contexts.

Primary pass criteria: exact independent rows and full policy populations on
assessable domains, exact same-head comparison, no future-report leakage,
full second-stage memory, and exact common-rule intersection on a shared domain.
Counterexamples declared before the run: between-date correction reports 7 then
6, not 6 then 6; identical numeric observations across worlds have identical
keys; a pair of individually satisfiable toy contexts with opposing required
actions at the same message has no common rule. No conclusion of existence may
be drawn from separate policies. Reversed source corrections, unknown access,
late conflict/retraction, actual-amendment interpretation, incomplete search and
overflow are explicit cases. Wrong row/world, future reports, lost memory,
fabricated candidates, wrong refusal witnesses and admission flags are controls.

Defaults and risks: financial rows, 6/7 receipts and rights are synthetic checked
fixtures; source clocks and maps are supplied assumptions; two actions and two
dates restrict the problem. Numeric cash/trigger observations are inherited
interfaces, not empirical evidence of manager knowledge. Report supplementation
is an explicit alternative. Early checks compare the original same-head case
and the between-date messages before accepting population results. Row counts,
candidate counts and runtime are explanatory; this is an exact finite comparison,
not a ranking, utility result, forecasting claim or production default.

At most three fresh 120-second CPU attempts; GPU hidden. Preserve inputs and
expectations before evaluation, source locks, full results, failures, manifest
and result note. Invalid source locks or oracle mismatch veto the comparison;
candidate error triggers bounded repair, overflow triggers a separate audited
domain-computation plan. No agents, fees, outreach, installs, publication or E3.
