39.7.3
Changing the index while preserving an insurer’s posting
An acquisition payment of 8 creates an acquisition asset of 8 and reduces cash by the same
amount. A later recoverability assessment reduces that asset by 3 and recognises an expense of
3. Suppose the first request has identity ("a/b","c") and the second has identity ("a","b/c").
The old slash key falsely conflicts the second request, even when it supplies the correct opening
owners and information view. Repairing the key must admit that second request while ensuring
that a retry of the first never pays the acquisition cost again.
InsuranceComponentsIdentity/1 supplies an explicit execution policy bound to the exact
InsuranceComponents/1 financial profile. Its identity record locks both the existing financial
schemas and contract and the new identity schema and contract. The financial profile, operation
names, original request bytes, immutable outputs and receipts retain their identities. Changing
the financial profile reference inside an old request would create a different request; it would
not constitute a retry of the old payment. Separating the execution policy makes the intended
change precise.
Conversion adds the policy reference to the declared world and replaces each decision-map
key with its canonical ordered pair. Every owner head, journal, published financial record,
original decision reference, current view and unrelated ownership field remains unchanged. Each
supplied historical decision must reproduce its original complete publication. Known missing,
conflicting or ambiguous histories refuse conversion. The order of entries in a JSON map
does not establish posting chronology: the converter checks the exact journal entries and their
multiplicities against retained decisions, then preserves the original journal sequence. It never
derives a new sequence from map order.
The new dispatcher checks the execution-policy binding and exact submission bytes before
examining a prior decision. An identical request returns its original output, receipt, diagnostics
and publication list with no additional commit, even after the current view and owner heads
advance. Changed bytes under that same pair conflict. A fresh pair still has to pass the original
full read set, evidence, authority, lineage and financial checks. The new identity format therefore
removes a false conflict without weakening financial eligibility.
In the two-event example, the successor retains the original acquisition and impairment results
and both journals. Each original request replays without another posting. Recovery also
reproduces the original publication when the acknowledgement was lost before commitment,
and returns the original receipt when commitment already occurred. The broader comparison
preserves all 672 retained exchanges, including 84 publications, and converts 127 distinct before-
and-after worlds. All 686 saved successor exchanges reconstruct. The checks also refuse a newly
hashed but financially wrong proposal, duplicate journals and ambiguous complete publication
histories.
These are finite documentary comparisons using the retained financial evaluator. They establish
the checked protocol correspondence, not physical store durability or a new independent
implementation of accounting. Conversion remains conditional on the supplied history being
complete: an erased decision with no surviving independent evidence cannot be discovered
from the index. The evidence and exact two-expression protocol change are retained under
data/accounting-master/insurance-identity-adoption-20261026/. The policy does not translate
these component owners into an insurance-assessment head; that receiving state still requires a
separately justified adapter.
