39.7.4
Declaring a dependency without inventing a state adapter
RetainedProfileComposition/1 provides a finite text and typed description of dependencies
between imported native exchanges. Each stage names a packet by its exact content hash and
selects an exchange identifier. The resulting description preserves its profile, request, result,
receipt, information view, native signature when present and complete publication effects. It
contains no financial formula or arbitrary execution callback.
A sequence dependency requires the same exact profile and equality of the complete predecessor-
after and successor-before worlds. A state dependency also names explicit paths to the produced
and consumed native state references. Those references must agree, and the receiving request
must actually declare the consumed head. Thus matching a closing cash amount cannot conceal
a changed owner, information view, journal history or decision index. A receipt dependency
requires the original receipt to occur in the receiving request’s immutable dependency closure;
that reference alone conveys no accounting authority.
The text form declares a composition name, ordered stages and dependencies. Its stage values
are an identifier, packet hash and exchange identifier; its dependency values are source stage,
destination stage, relation and two explicit head paths when the relation is a state handoff. All
values are data. The typed form carries the same closed fields, and source-line locations are
retained separately from semantic identity. The checked text and typed routes produce identical
native findings. Existing annual-program authoring and declared-method requirements keep
their own evaluation rules; this layer does not replace them.
Consider passing an insurance component’s closing accounts to an insurance assessment. The
former is an OwnerState containing a ten-account balance map and component history in a
scenario-specific context. The latter expects an AccountingHead with a balance digest in a
different entity, authority and information context. Both examples use USD, but that agreement
supplies neither an ownership mapping nor a complete accounting-state conversion. The direct
handoff is unsupported. An adapter would need explicit entity and book matching, balance
and history mapping, temporal and source admission, applicable authority, and checked native
request/result bindings.
Unknown acknowledgement makes dependent stages unresolved, including later stages whose
immediately adjacent worlds otherwise match. A partial query can publish evidence without
supplying a completed financial successor. A refused stage cannot supply a dependent input. The
comparison preserves all these findings even when another defect determines the overall status.
Duplicate publication decisions, missing imports, cycles, undeclared intervening changes and
incompatible head references are refused. Stages with no declared edge are merely independent
in the description; they are not certified for concurrent execution.
