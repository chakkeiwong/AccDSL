# Existing return and lease states cannot be combined directly

24 October 2026. Eleven saved cases and seven focused test methods distinguish
valid same-state controls, incompatible native profiles, unknown context or
membership and malformed/stale requests. Both original positive proposals
replay exactly. Their journal sums, cash-flow reconciliation, account deltas
and unchanged memory fields pass. All 113 protected inputs remain intact.

The original return book has 22 accounts and the lease book 26. They disagree
on legal owner, date, period and state schema. Shared account names establish
no cross-profile meaning. Return settlement changes component state, lots,
tax adjustments, balances, flows, date and event history. The retained lease
reduction changes leases, balances and event history. A field union would
violate both validators and omit necessary common-book semantics.

The code review found an unknown field could mask unrelated invalidity. The
classifier now treats only an explicit native unresolved status as missing
evidence; a regression combines an unknown component input with an unbalanced
book and requires incompatible. This repair changes no frozen native code.

These are deterministic engineering checks, not stochastic rankings. The
weakest evidence is cross-profile account semantics, which remain unresolved
and are never inferred from names. A future explicit shared-state design with
checked mappings could remove that incompatibility; this result does not
invalidate the underlying methods or whole simulator program.
