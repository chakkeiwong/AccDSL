A.55.1
Which members are actually known
MethodCollections/1 declares typed collections and selected constraints over their fields. Its first
operations are uniqueness, exact-one reference resolution, nondecreasing order, and a guarded
requirement evaluated for each row. Global inputs and row inputs have explicit mappings to
the preserved guarded evaluator. Type, context and role must agree; a field name does not by
itself establish economic equivalence.
A supplied collection is either complete with its rows, or partial with its observed rows and a
reason for incomplete coverage. Missing collections are partial with no observed rows. Partial
rows retain their relative supplied order, while additional members may be absent between
them. An unknown field has a separate tagged reason. Thus an empty complete list says that
there are no members in the declared scope; an empty partial list says that none has yet been
supplied. These are different assertions, and neither proves that the scope describes an actual
company’s complete record.
Known duplicates contradict uniqueness even when another key is unknown. When no duplicate
is observed, an unknown key or incomplete membership prevents a uniqueness conclusion. A
reference must resolve to exactly one matching target of the same type and context. Two
known matches already contradict that requirement. No match is a contradiction only when
the target collection is complete and its keys are known. One known match remains unresolved
if another unknown or unobserved target could create a second match. Target-wide uniqueness
is a separate condition when needed.
Ordering checks preserve the caller’s sequence. If two known dates are reversed, an unknown
date between them cannot repair the reversal. If the known subsequence is ordered but another
date or member is unknown, the full order remains unresolved. Equal dates retain their original
order rather than being sorted by a hidden tie-breaker. Period predicates separately check
the retained half-open interval: an event on the start date is included, while an event on the
exclusive end date is outside the period.
Per-row checks retain all original guarded findings and indexed input mappings. A known
invalid row remains visible despite another unknown row or incomplete membership. An inactive
condition still undergoes type and structure checks, and its separately required facts remain
required. A complete empty collection vacuously satisfies a universal row condition; a partial
empty collection leaves it unresolved. These rules prevent missing records from being mistaken
for a successful review of every record.
A.55.2
A sale needs an earlier live lot
Snapshot membership cannot show that a lot existed before a sale. The retained comparison
makes this concrete by giving settlement and sale the same date and placing the sale first.
Date ordering then passes, but the native method rejects the sale because the lot does not
yet exist. A second sale and a second complete settlement expose similar limitations. These
failures motivate an explicitly ordered identity check rather than a stronger interpretation of
the snapshot.
MethodIdentityLifecycle/1 declares named identity pools, their initial live and retired members,
and a closed action mapping. Each action contains an ordered list of create, require or consume
operations. Create requires an identity absent from both live and retired memory. Require
checks that an identity is live without changing it. Consume moves a live identity into retired
memory. Retaining retired identities prevents an already used identifier from being silently
created again.
