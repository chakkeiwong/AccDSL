# A return method in one legal book

The retained CompanyComposition migration already maps a supported return
component and checks a following settlement against its original after-state.
Reuse that method and all original identities. The new boundary concerns how
a caller owns the shared books, authorizes a finite invocation, and applies
one checked state delta without adding the component's opening cash or equity
again. It is a pure proposal reference; persistence and native Northstar
operation authoring are subsequent work.

The positive example remains Synthetic-return-expected / Legal / base, dated
2024-06-30, with its original source context and view. Original cash is 100;
settling two returns pays 40 refund and 8 handling, receives inventory of 20,
reverses recovery asset 16 and refund liability 40, credits cost of sales 4
and debits selling expense 8. Cash ends at 52. These are retained synthetic
facts, not observations about Northstar or new accounting-policy choices.

The caller supplies a world of separately identified legal books and a
request that binds the entire current world, original state/context/view,
method descriptor, event and account map. The binding authorizes only the
exact retained event and supported projection. A locally selected trusted
method supplies the transition; packet data cannot select code. The component
uses the named book's existing balances and accumulators. The resulting
proposal contains the journal, gross/net cash effects, updated component
memory and complete proposed world. A non-target legal book is unchanged.
The proposal is uncommitted and grants no historical or source-time admission.

The method footprint identifies mapped book accounts, component memory,
sequence/date and accumulated cash/OCI/equity. Changed owner, context, view,
source bytes, method, state or event refuses before invocation. Unknown or
false facts retain their distinct unresolved/unsupported meaning. The exact
positive mapping is checked against both retained after-state and independently
calculated journal/cash effects. No inferred tax expense or annual report is
added; the predecessor explicitly labels tax component-scoped.

Northstar currently has no refund liability, recovery asset, return-right
memory, recovered-stock valuation, required source findings, or native
return-settlement kind. Its context and periods also differ from this retained
state. A portable reference cannot repair these differences. The adapter must
refuse that join, and the native extension must explicitly add the missing
state, account/report classification and authoring semantics before execution.
SectorCompany remains report-only, with no journals or state mutations; that
method cannot be silently used as a posting module.

This boundary is narrower than a general module registry. It accepts one
protected event/state transition and exposes the responsibilities needed for
a later compatible native module. Existing source and wider corporate,
financing, bank and insurance residuals remain unchanged. The coverage result
is a specific integration contract, not a new completion claim.
