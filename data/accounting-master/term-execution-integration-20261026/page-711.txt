Check the proposed result before continuing.
The command composition checks the
selected snapshot before eligibility and again after the typed transition. A well-typed but
incorrect predecessor or overdue write can pass construction and still fail the resulting historical
requirements. In that case the result retains diagnostic transition evidence but does not return
an accepted top-level after-state. The caller cannot continue the sequence from that rejected
proposal. The successful path remains a provisional calculation; it performs no durable commit
and does not establish source or accounting admission.
Period carry follows the same discipline. Its report request must bind to the exact closing book.
The selected policy preserves all typed memory leaves, including immutable term and assessment
histories, and resets only the assessment cursor to the next period’s start. The preserved report
and carry engines produce the closing and opening books, which are checked against the selected
snapshot contract. Completeness of the supplied population is carried forward only from the
accepted pre-state through this declared transition; it is not manufactured for an unrelated
supplied book.
Chronology is visible in the complete comparison. Each company’s retained sequence contains
nine events, with carry between the seventh and eighth events. The continuation uses the
computed output of each command as the next input, including carry. Appending carry after
all nine events, or resetting the input to a stored snapshot before each event, would not verify
this chain. The final state agrees only after the commands are placed at their actual positions
across the two fiscal periods.
Make the selected behavior directly authorable.
The state-contract source spells
out structural stages, nested projections, queries, captures, template substitutions, guarded
requirements and collection constraints. Event-rule source separately spells out eligibility
bindings, typed parameters, method conditions, monetary effects and nested writes. Carry policy
has its own short declaration. These source forms contain the algorithm-bearing declarations
rather than an opaque import of a completed financial algorithm. JSON tokens remain available
for explicit types, contexts, schema expectations and scalar data.
The frontend preserves authored declaration order and exact Unicode strings. Only line-feed
characters split source lines; carriage-return/line-feed input is also accepted without mistaking
a Unicode line separator inside a string for a new declaration. Locations record physical line
numbers and UTF-8 byte slices. Lexical errors identify tokens or declarations; failures reported
by an opaque contextual validator identify the responsible source component, without pretending
to identify a more precise field.
Parsing, eligibility compilation and contextual construction remain distinct states. A parsed
construction is not reported as contextually compiled until its event and book have been supplied.
Execution also requires the independently supplied selection of the combined contract and rules.
Changing a source file does not authorize its changed declaration: the old selection refuses
it. Source diagnostics are retained alongside the complete typed execution result, so adding
location information does not obscure the comparison with that result.
