A.54.22
Carry the historical terms through a complete command
The historical checks in Section A.54.21 answer whether the supplied terms and assessments fit
together. They do not, by themselves, justify changing the claim. An amendment also needs
a valid current state, an identified customer and prior term, an admissible effective date, and
a complete description of the writes it will perform. A collection must change the remaining
receivable without rewriting its earlier assessments. At a period boundary, closing entries and
the next assessment window must agree. These are connected requirements: accepting each
snapshot in isolation would leave the correspondence between the event and the financial history
unchecked.
The selected continuation described here joins those checks for the retained synthetic claim.
It covers prospective due-date amendments, collections, assessments and period carry. The
accounting premise is still deliberately narrow: an amendment changes the supplied terms
without recognising a modification gain or loss, interest or impairment. Actual contractual
applicability and the appropriate accounting treatment require their own evidence. Within this
premise, the implementation question is precise: can explicit declarations produce the complete
retained requests and results while the native financial builders are disabled?
Establish which supplied state the declaration accepts.
The selected state contract
combines structural checks with the six historical and financial checks already described.
Structural checks require the exact state fields and profile, a typed book, the declared term-
claim and clock schemas, the operating account roles, a positive cost leaf with the expected
units, and the stated migration fields and premise. The account selection is explicit. A different
cost pointer can be valid under the native validator and still fall outside this selected contract;
refusal then means that the selection does not cover that configuration.
Existing admission stages evaluate most of these conditions on a normalized view in which the
original book field is named opening. The original envelope is checked first, and normalization
preserves every value and its insertion order. The reused stage engine’s internal success label
does not turn a mid-period snapshot into a new-period opening. The enclosing result reports
satisfaction of the selected snapshot contract and retains false opening, source and accounting
admission flags.
Two additional conditions are explicit. The migration source-book identifier must have the
syntax of a SHA-256 digest, and every term premise must contain nonblank text. The distinction
between text and nonblank text matters: a space-only premise can satisfy the generic text type
while failing the native premise requirement. Checking a digest’s syntax establishes neither
the existence nor the truth of the referenced source. Similarly, complete supplied claim and
nested-row populations remain a stated input scope. A partial population leaves the command
unresolved before construction.
Resolve the event against the same history.
For an amendment, eligibility first checks
the event’s identity and date, the complete typed inputs, and the supplied approval. Unknown
inputs produce an unresolved result. An explicitly unselected approval produces an unsupported
result. These outcomes differ from invalid state, stale selection, duplicate event or contradictory
dates.
