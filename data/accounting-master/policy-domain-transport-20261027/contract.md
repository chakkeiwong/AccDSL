# Domain-transport audit: first relation is exact renaming

27 October 2026. MC03/05/11/12/13/18/24/25/26/28/33/34;
W03/04/11/12/13/16. Profile ProspectivePolicyRenaming/1.

The next-plan audit exposes a structural limit. Both domains are generated from
the same complete original source registry and finite action rows. If every raw
observation has one old key and one new key, a consistent injective mapping
covering every raw occurrence necessarily covers every generated new key.
It is a bijection on generated keys, not genuine domain expansion. Calling
this an extension would be wrong relative to the proposed target.

First implement the useful exact subcase: a global one-to-one renaming of the
first-message tokens and separately of second-message tokens. Check every raw
key in every original observation head,not only reached or selected heads.
Retain actor,dates,actions,source identities,tag rules,resource limit and original
request. Refuse split labels and merged labels. A correction-specific rename
that splits one shared old label into two new labels is a changed observation
partition and remains outside this relation. This is a local scope refinement;
the broader domain-change question remains open,not silently closed.

Build old/new policy-key pairs from every original financial/observation head
and every preserved numeric row. Require a bijection with exact first/second
stage and own-action memory correspondence. Preserve each row's action and
refusal meaning. For a fixed checked frontier,compare first-stage unary and
second-stage binary forbidden assignments under that permutation. A new total
rule satisfies the new constraints exactly when its permutation back satisfies
the old constraints. Derivation: each forbidden conjunction has the same action
bits and corresponding key positions;the truth value of every conjunction is
unchanged. Their disjunction,its negation,and therefore the full candidate set
are unchanged under permutation. No probability or financial ranking is implied.

Primary criterion: exact equality between permuted old candidates and fresh
new candidates,plus independent oracle equality. Include nonempty unary and
binary restrictions,and pending/unknown/inconsistent cases. Save both domain
identities,full relation,old/new result identities,source supports and pending
records. The new result keeps its new identity;this is not accepting an old
cached record as if nothing changed. Changed original requests,actions,actor,
source hash,timing,stage,split/merged labels and false candidate transport veto.
Over-budget/no-domain cases return unsupported relation,never truncate.

Defaults:finite12-key binary scope inherited,not promoted. ASCII prefixes in
renaming fixtures are convenience labels;test stage-specific and reversible
alternative spellings. Complete saved original inputs are synthetic baselines.
Counts/time describe only;exact set equality and constraint correspondence decide.
Use the domain-transport plan's three120-second CPU attempts. No agents,GPU,
installs,commits,fees,outreach,publication or E3. Preserve original result files.
Next discriminating question after this subcase: how a genuine observation split
changes available policies and whether any nontrivial sound reuse remains.
