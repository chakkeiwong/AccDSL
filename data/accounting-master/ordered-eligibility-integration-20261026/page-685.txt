A.54.14
Preserving the order of eligibility decisions
A customer can be unknown before a collection is authorised. Suppose the full intent supplies
an unknown customer, false approval and a claim key absent from the book. The retained
lifecycle first reports unresolved input. Once the customer is supplied, the same false approval
produces an unsupported event; only after approval can the missing claim produce an invalid
event. Combining all three predicates into one conjunction changes this behaviour: an invalid
consequence can outrank the earlier unresolved or unsupported result. The individual predicates
remain meaningful, but their conjunction computes a different decision.
OrderedEventEligibility/1 makes this order explicit. A template declares its company context,
operation, complete input types and ordered stages. Each stage supplies one existing guarded
requirements manifest, exact bindings for its declared inputs, and the reason to report if it
does not pass. The evaluator validates the typed book, event identity, chronology, full input
population, types, values and provenance before interpreting the stages. Any unknown full
input then returns unresolved, preserving the input names. Approval is the first semantic stage
in each retained template. A stage with no active requirement is refused rather than treated as
permission to continue.
For a sale or collection, the next stage checks that assessment has not sealed the event date.
A sale then checks the due date and absence of the claim key. A collection checks presence of
the key before comparing its recorded customer with the supplied customer. An assessment
instead checks its starting cursor, nonempty interval and last included date, then its period
boundary. Execution stops at the first stage that does not pass, retaining its status, reason
and stage identifier. The existing guarded evaluator still determines each typed predicate; the
ordered layer introduces no competing Boolean language.
The bindings supply facts rather than conclusions. They can read a full-intent input, event
identifier or date, book date or period end, a declared memory leaf, map membership, or a
selected row’s scalar field. Membership is computed against the actual typed map using the
supplied text key. A caller cannot replace that computation with an asserted Boolean. A
