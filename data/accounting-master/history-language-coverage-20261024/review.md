The four inspected conditional modules expose validated Python definitions and
assessment calls. They have no corresponding strict text decoder in those modules;
existing method requirement text is limited to its own explicit profiles. This is
a genuine authoring gap within the inspected contracts, not proof that the whole
repository lacks a parser. MC24 keeps that gap open. It is not the first repair
because it would leave the same monetary-only state semantics unchanged.

MethodRequirements/2 already checks rational dimensions, complete context and
positive scales, and computes product types. MethodMonetaryEffects/1 derives
fixed typed products; MethodMemoryEffects/1 stages known structured records.
Neither is the conditional unknown history with constraints at each event.
ConditionalMonetaryHistory/1 explicitly rejects nonmonetary value types, assigns
one type to every memory amount and reports operational preconditions unchecked.
Its exact symbolic opening and replay remain valid within that restriction.

The selected next dependency is a separate TypedAffineHistory/1: quantities and
money coexist through explicit typed constant coefficients, and authored state
constraints are enforced at opening and every event. The discriminating example
has balanced closing statements but an impossible intermediate stock path under
an explicit no-negative-stock premise. Reversing same-day sale/restock order must
matter. Omitting the premise leaves it unchecked; no operational truth is invented.

Nonlinear unknown prices, general native methods and endogenous candidate
generation are still open. The history architecture H1–H4 distinguishes proposal,
admission, formula construction and search, but those stages require broader
method and source obligations. A finite affine extension cannot close them.
