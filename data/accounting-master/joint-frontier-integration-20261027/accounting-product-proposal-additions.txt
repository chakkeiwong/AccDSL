This document specifies a system that translates company disclosures into traceable evidence,
represents several compatible economic and accounting histories, and simulates their future
journals and financial statements under explicit economic scenarios.
The proposed data contracts, methods and acceptance cases specify the intended implementation.
Current source and domain limitations remain explicit; this candidate is not a completed product
or a claim of full proposal readiness. Proposed libraries can be replaced while preserving those
contracts. Sector rule packages require their own accounting review before they can be described
as compliant with a reporting standard.
Research materials, source qualifications and review records accompany this document in
docs/design/research and docs/design/review.

17.23.2
Use the selected map at each stage
A prospective policy domain must now cover more than same-head combinations. Before
inspecting completed joint outcomes, the declaration crosses the original financial head with
every assertion-valued first-stage observation head and every assertion-valued second-stage head.
It constructs the first message from the first selected map and the second message from the
second selected map. The second decision key retains the actual first message and the manager’s
own first action. Internal head identities remain support records, not messages visible to the
manager.
In the inherited raw observation schema, coarse versus refined changes only the first observation.
The second raw observation remains the trigger and cash-coverage pair. Selecting a different
source head at the second date therefore does not, by itself, add second-stage information. An
explicit change to a second-message token tests whether the correct stage map is used, while
remaining a supplied interface assumption.
That changed-token case needs 15 keys in the conservative original domain, exceeding the 12-key
allowance. It remains unresolved without dropping mixed-stage combinations. A separate
diagnostic collapses the first messages and uses 7 keys. Its encoded second messages differ
when the wrong first-stage head is substituted for the second-stage head, so the test detects
that wiring error. The correctly wired diagnostic nevertheless has no feasible policy. Correct
source-to-message binding and policy feasibility are separate conclusions.
With the original mappings, arrival between the decisions or after both leaves 16 total rules on
the conservative 11-key domain. Some assignments concern keys not reached in the selected
family; these are not 16 demonstrated reached behaviors. Arrival before both dates supplies the
coarse first view and leaves no feasible rule. The interval containing all three sequences also has
no common rule because it includes that coarse-first history. Unknown access preserves the
same conditional family and its infeasibility, without turning unknown access into an observed
fact.
A required retracted or conflicting source view leaves the overall policy question unresolved,
even when candidate assignments satisfy every known numeric constraint. Inconsistent clocks
and either temporal or policy-domain budget exhaustion supply no feasible-policy answer.14
These results bind a complete joint source family to two-stage decisions. Continuing an unfinished
joint search, changing financial rules between dates and admitting actual actor information
remain separate tasks.

Each unfinished branch retains the constraints accumulated on the original clock variables.
At a branch concerning a particular source and decision date, the alternatives are that every
eligibility condition holds or that a named condition is the first to fail. These alternatives
cover the parent branch without overlap. The search creates all of them before pausing. It can
therefore resume from the first pending branch while preserving every other pending branch, the
first decision’s eligibility choices and the second decision’s remaining tests. A short allowance
changes how much has been examined, not the question being asked.
The saved state distinguishes a per-call allowance from a total node cap. Reaching the total
cap leaves a capped, incomplete result with its pending domains. A checker reconstructs each
branch’s constraints from its path, verifies the rational feasibility or contradiction evidence and
recomputes both selected source views at completed leaves. Checking only the number of leaves
would miss a lost or duplicated support region. In the bounded examples, resuming one node
at a time, seven at a time or without intermediate pauses produces the same complete tree,
joint outcomes and support paths.

This is a local set-theoretic consequence of adding restrictions in the same rule universe. Initially
no source pair may have been selected, in which case the empty intersection imposes no
restrictions and C0 = Π. That initial survival says nothing about financing feasibility. Each
newly selected pair can remove a rule; none can restore a rule already rejected by a known pair.
The index k measures search work, not elapsed financial time, so this relation does not describe
how a manager’s information evolves.
If the known restrictions leave no rule, no completion that merely adds further source pairs
can supply a rule satisfying all of them. Conversely, a nonempty Ck remains a partial answer
while any source region is pending. In the correction example, a completed coarse-first pair can
already remove all candidates, whereas observing only refined-first pairs cannot establish that
no coarse-first pair remains. A changed source declaration or message domain would alter the
comparison and requires a separate justification for reusing old results.
The returned conclusion also preserves the reason a family is unresolved.
A retracted or
conflicting required source remains an unresolved source view; the overall result keeps that
status even if the known restrictions separately rule out every candidate. A complete timing
family with unknown actual access is instead evaluated conditionally on all its supplied possible
arrival sequences. Inconsistent clocks supply no admissible joint sequence and are not treated as
a feasible empty family. Exceeding the prospective key allowance leaves the policy population
unassessed. Only a completed search with selected source content and surviving rules supports
conditional feasibility under these declarations.

17.24.2
Check the reason for each rejected rule
A saved list of surviving rules is insufficient evidence by itself.
For every excluded total
assignment, the result names a known financial row that refuses it. A first-stage refusal must
match the rule’s first action at that row’s message. A second-stage refusal must also match
the second action, using the second key that retains the actual first message and action. The
checker validates these witnesses and requires the surviving and rejected assignments together
to cover the entire fixed rule universe. It also reconstructs the conclusion, unknown source pairs,
pending domains and support paths from the checked source search.
The finite comparison checks every saved endpoint and selected partial results against an
independently evaluated policy population.
Altered refusal witnesses, premature feasible
conclusions, missing pending evidence and changed identities are rejected. The result checker
still uses the established source-to-row mapping and policy oracle; it is not an independent
redevelopment of all accounting and observation semantics.15
This establishes logical continuation for the supplied two-date question. It does not test crash-
safe file storage or establish actual information delivery. Transporting a result to changed
observation declarations, extending the horizon and admitting company evidence require further
work.
