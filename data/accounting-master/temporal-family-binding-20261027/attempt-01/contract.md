## Interface/default audit and skeptical review

The accepted exact temporal predecessor returns a full verified proof tree when
complete, but throws away its partial tree on budget exhaustion. Therefore this
successor cannot honestly claim a saved resumable frontier. It carries the entire
original prepared clock domain as a conservative unresolved remainder, with no
certified completed view and no policy payload. This preserves the question and
all unprocessed possibilities while permitting duplicate future work. A precise
incremental frontier needs a separate successor. The cheap diagnostic is a one-node
budget request: complete=false, no policy payload, full original domain retained.
This inspection corrected an otherwise misleading interpretation of the next plan.

External expected input identities cover request, full source/record/observation
maps, caller trust set and node budget. The executed temporal implementation and
its loaded dependencies are separately bound to protected predecessor hashes.
A saved envelope additionally needs an expected identity held outside it. An
internally recomputed digest supplies no trust. Tests also change inner checksums
and use structural verification to expose incomplete proof support.

All nonempty proof leaves retain their exact tree paths and outcome identities.
Equal scenarios may share the complete numerical payload, but every source head,
unknown clock, original precision and proof support stays in the family. Different
observation mechanisms retain distinct scenario keys even if both have zero
policies. Policy tables with different action domains are never intersected.
The six-revision/4096-node bounds and chronology/public-private profile are inherited
hypotheses from the exact predecessor, not general information-practice defaults.
Exact-boundary, changed actor/channel, correction, trust withdrawal and changed
financial-family cases diagnose those limits early.

Numerical evidence is externally pinned to previously protected rows, complete
policy comparisons and method sources; a reused payload must match the complete
locked scenario reference and row IDs. Cold calculations use both existing policy
formulations. Test comparisons preserve full values rather than comparing counts.
The existing standard-library Python CPU environment is a convenience choice;
no stochastic ranking or default change is involved.

## Execution and stop rules

Inspect interfaces -> this audit -> small import/base/budget diagnostic -> bounded
full comparison -> adversarial transport controls -> source-preservation check ->
result/reset memo and master continuation update. At most three fresh120-second
attempts; never rerun accepted writers. Preserve failures and repair the cause.
Stop only on invalid evidence, changed protected sources or an unresolved hard
correctness error. Continue independently ready internal work if a candidate fails.

Artifacts: family.py, cases.py, verify.py; diagnostic-01/; attempt-01/ (or numbered
repairs); source-lock and run manifest; result.md and next-plan note. Every serious
result records decision, primary/veto status, uncertainty, next action and limits.
No GPU, installations, agents, fees, outreach, actual journals or publication.
