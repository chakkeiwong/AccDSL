# RetainedProfileComposition/1

This finite comparison language imports exact retained exchanges by packet hash
and exchange id. It declares ordered stages and dependency edges; it contains no
financial formula, posting callback, implicit state converter or code loader.
The existing annual-program compiler continues to own its supported financial
operations, and MethodRequirements/1–3 continue to own their declared predicate
evaluation. This layer does not repeat either evaluator.

Each stage retains its complete PublicationEffects/1 descriptor, request view,
context reference when present and native signature reference when present.
The packet bytes and exchange references are checked against the frozen lock.
No missing signature is invented for profiles without that native record.

There are three dependency relations. A sequence requires the same exact
profile and byte-equivalent complete predecessor-after/successor-before worlds.
A state dependency additionally selects explicit keys under the native head map
on both sides. They must name identical references and no intervening changes
may be hidden. A receipt dependency requires the exact original receipt to
occur in the receiving request's immutable dependency closure. It only establishes
reference use, not that a receipt grants financial authority.

A source stage with an unknown acknowledgement leaves its dependents unresolved.
Replay supplies its original receipt with no new effects. A partial query can
publish evidence, but a state handoff requires a completed/replayed source; it
does not upgrade an unresolved financial result. A refused source makes its
dependent unavailable. Unsupported cross-profile adapters remain explicit.
All edge findings survive the summary; invalid dominates unsupported, then
unresolved. Every result retains execution_admission=false.
Unavailability propagates through dependent stages, even when a later pair has
locally matching worlds. The report retains the predecessor responsible for it.

The concrete incompatible pair is InsuranceComponents/1 OwnerState for accounts
and InsuranceAssessment/1 AccountingHead. The former retains a ten-account
balance map and component history in a scenario context. The latter names an
accounting head and balance digest in a different entity/authority/information
context. Equal currency is insufficient. An adapter would need an explicit
entity/book/context match, complete balance mapping, temporal and source-view
admission, authority applicability, retained history and tested request/result
bindings. None is supplied by this comparison.

The text grammar is line-oriented: composition PROFILE NAME; stage ID PACKET_HASH
EXCHANGE_ID; depend FROM TO RELATION PRODUCED_PATH CONSUMED_PATH; end_composition.
Every value is a JSON string or list token. Paths are lists of exact map keys;
numeric indexing, dynamic paths and filesystem imports are unsupported. Typed
plans carry the same fields. Line positions are separate from semantic identity.
The existing strict lexer is reused. Bounded stage counts are engineering limits,
not financial assumptions.

Positive evidence must come from retained native commit/report and retry
sequences. Independent stages mean only that no dependency is declared; they
are not assumed disjoint or safe for concurrent execution. Duplicated publication
decisions, cycles, missing stages and false receipt/state bindings refuse.
No claim of general all-method authoring, temporal admission or production
composition follows from syntactic or documentary consistency.
No retained receiving request consumes a receipt in the four pinned packets.
The receipt relation is specified and refusal-tested; its positive use remains
unexercised and is not included in the checked native sequence claim.
