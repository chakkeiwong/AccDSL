13.5
Correction changes a view without rewriting its history
A correction can affect a result that never explicitly selected the corrected source. Suppose
a query selected one available report because it was the only eligible candidate. Admitting a
second report may create a conflict. The query therefore depends on candidate-set membership
as well as on its selected record. Invalidation must follow both dependencies transitively.
Each correction creates an immutable new view with parent and changed decisions. Old frozen
outputs retain their original views. A current query must check ancestor dependencies even for
descendants created after an invalidation scan; otherwise delayed computation could revive a
stale reading. Unrelated closures remain usable. Self-supersession, incompatible replacement
scope and a missing required predecessor reject before mutation.
The mathematical correction and the audit of affected work are separate records.
A
CorrectionBasis depends on the unaffected base law, replaced reading, corrected source, target
admission and replacement method.
An InvalidationReport additionally depends on the
inspected store snapshot and lists affected descendants. Computing another optional descendant
changes the report, not the corrected law. This also keeps the content-reference graph acyclic.
Probability calculation, admission and selection are three effects. A selected law belongs to the
owner consisting of family, target evidence view, target time and purpose. Correcting a source
does not mutate the old owner’s selected pointer or automatically select the new candidate
posterior. In the new owner, an inherited stale selection returns selection superseded with an
explicit readmission and reselection obligation. With no inherited selection it returns selection
required. A historical query naming the old view remains valid in that frozen scope.
13.6
Durability and migration have observable obligations
One logical transactional store owns records, dependency edges, review views, branch heads,
journals, economic deltas, receipts and search checkpoints.
Original documents reside in
immutable byte storage. Their exact bytes must be durable and verified before a metadata
transaction refers to them. A crash between blob creation and metadata commit may leave an
unreferenced blob; it must not leave an accepted reference to absent bytes. Analytical tables,
caches and PDFs derive from a named snapshot and do not become separate writable versions
of truth.
