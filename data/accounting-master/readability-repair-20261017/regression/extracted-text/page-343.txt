13.13.2
Equal amounts still have separate source occurrences
Suppose an issuer repeats one tagged amount in a statement and a note. A query may need
a single amount, but an auditor still needs both locations and the evidence that they agree.
These are different requirements. The proposed exchange preserves each occurrence before
constructing a view that groups facts for a particular question. The inspected Arelle methods
make the reason for that separation precise: displaying a value, comparing two values, grouping
facts with matching aspects and removing repeated facts perform different operations (Arelle
contributors, 2026a).
A displayed value is particularly unsuitable as the retained amount.
The effectiveValue
property produces a view: it rounds and formats numbers, represents nil with a string, and
can return an error description. Even a convenient numeric property needs scrutiny. The
inspected vEqValue converts numeric text to a binary floating-point number. The distinct integers
253 = 9,007,199,254,740,992 and 253 + 1 then have the same floating-point representation. This
constructed example does not describe an issuer error; it shows why that conversion cannot
establish exact identity. The adapter therefore keeps the source literal, the typed value and
the displayed reading as distinct fields, with the transformation between them recorded (Arelle
contributors, 2026a).
The same caution applies to a method whose name contains equal. In the inspected isVEqualTo,
the ordinary numeric comparison checks context and unit and follows the selected rounding
mode, but the method does not itself compare concept names. Its nil branch returns whether
the other fact is nil before comparing contexts. A caller needing facts about the same accounting
quantity must establish that condition separately. Conversely, the item branch of isDuplicateOf
checks concept, parent, context and numeric unit without comparing the item values. It can
identify candidates for investigating a disagreement; its result does not resolve that disagreement.
The tuple branch has additional child comparisons and must not be described as the same test
(Arelle contributors, 2026a).
The dedicated duplicate-fact module supplies more explicit grouping. It checks concept, context
and unit after forming hash buckets, and includes language for the relevant text-fact types.
Its value tests nevertheless remain specific to the operation. Consider two hypothetical valid
numeric occurrences with the same concept, context, unit and declared decimals of zero, whose
value strings are 1 and 1.0. In the inspected code, the ordinary value-equality key retains those
strings, so the all-complete classification distinguishes them. The complete-subset reduction
instead keys on declared decimals and the typed value; decimal one equals decimal one, so it
retains the first occurrence. Thus even within this module, the classification and reduction do
not share one universal equality key. The source strings and membership of a reduced view
must remain recoverable (Arelle contributors, 2026a).
