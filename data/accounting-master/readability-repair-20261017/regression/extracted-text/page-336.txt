A search checkpoint commits the semantic manifest, partition identity, explored and unresolved
regions, frontier, used budget and result references together. A cell is not complete before its
result and frontier transition are durable. Resume names that exact checkpoint and manifest.
Increasing a scheduling budget can continue it; changing evidence, methods, scenario, family or
traversal meaning requires a new manifest and an explicit reuse relation. Cancellation preserves
the last committed frontier.
Export first stages a closed manifest, verifies every required record and blob, then publishes
the manifest atomically. An incomplete export remains explicitly incomplete. Import verifies
required bytes before committing metadata and grants no new financial admission. A failed
report export cannot undo a journal or justify posting it again.
A representation-only migration retains old and new bytes and IDs plus a field/meaning mapping.
Its input names the old and new schemas, migration method, source snapshot and declared
semantic relation; the common request envelope supplies the expected head for its transaction.
It must preserve typed quantities, context, uncertainty category, reference closure, admission,
event identity and supported reference query results. Changing a rounding policy, calendar,
recognition rule or probability law is a new model, not a format migration. A failed comparison
leaves old heads and objects usable.
Exact reruns compare values on the same evaluated domain. An elapsed-time cap can visit
different search cells on different machines, so equal partial coverage cannot be presumed.
Reproducible prefix comparisons need a pinned traversal and operation-count budget; resume
uses the saved frontier. Approximate methods use their declared financial error comparison,
and random streams name economic owner, date, shock kind and draw index independently of
branch order.
13.7
Plugin interfaces
Every plugin declares a version, supported types, input information dates, determinism, nu-
merical measure and capabilities. A contract plugin implements schedule, observe, transition
and payoff; it may return future conditional events. A behaviour plugin implements decide
and declares which state and scenario information it uses. A measurement plugin implements
measure and returns an amount or vector with a basis and numerical status. A reporting plugin
maps classified journals and balances to output contexts.
The plugin response must include all inputs that materially affect results. An external calculator’s
global evaluation date, market-curve cache, calendar version or random seed cannot remain
invisible. For example, QuantLib’s floating coupon interface makes fixing-date conventions and
pricing objects relevant inputs; the adapter records them rather than relying on process-global
state. ACTUS risk-factor observations receive explicit dates and identifiers.
The constraint interface accepts a typed formula and a requested operation: feasibility, witness,
enumeration of declared finite choices, or bound. It returns sat, unsat or unknown, plus evidence
appropriate to the operation. Timeouts and unsupported theories return unknown. The history
layer exposes that solver outcome as SolverIncomplete, retains the affected region and marks
its coverage unresolved. These are layer-specific descriptions of incomplete computation, not
infeasibility. A witness proves existence within the formula, not completeness of a recovered
historical family.
