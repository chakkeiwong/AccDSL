Calendar adjacency is a narrow additional binding. After strict date validation, it compares the
two date ordinals and returns true when the right date is one calendar day after the left. An
assessment therefore relates its event date to its explicit end-exclusive date without constructing
a successor that could overflow at the maximum representable date. Leap days and year changes
follow the same relation. This is a civil-calendar condition, not a business-day adjustment
or a fiscal-calendar policy. The unchanged chronology and interval checks remain separate
conditions.

A.54.15
Executing declared event rules through a company program
A collection that works in isolation can still fail in a company program. An earlier sale changes
the claim population and its state schema; a report advances the observation date; a year-end
carry establishes the next opening book. The method for a later event must be constructed
from that current state. Replaying a previously finished method cannot establish that these
dependencies are handled correctly.
DeclarativeEventCompanyProgram/1 composes the explicit mechanisms. The program supplies
its opening book, typed memory definition, report mapping, authored state invariant and
one eligibility/construction pair per operation. Event commands contain the full intent. An
assessment also supplies an ordered list covering its current claim population. The program
contains neither native event callbacks nor precomputed event results. Separate hashes bind
the selected rules and invariant; program identity also retains the order of event inputs.
