# Proposed E1 metric profile and its boundary with E3

E1 asks whether a converter preserves a declared disclosure package and its
financial context. E3 asks whether preserving alternative histories improves
defined forecasts under the same economics. The newly inspected table metrics
help diagnose E1 components; they do not replace E1's context/value criterion
or supply E3's predictive evidence. The existing E1–E6 protocol and 3.44 targets
remain the comparator for this additive specification.

For E1, freeze a package inventory before candidate output: statements, notes,
policies, referenced documents, page/span locations and every required source
unit. Reference records need independently located transcription plus entity,
perimeter, concept, dimensions, unit/scale/sign, precision, period and unresolved
readings. A parser cannot label its own evaluation. Retain disputes and
unavailable labels rather than choosing the interpretation that favors a model.
The current source panel is a development resource, not a representative test
population or a substitute for independent annotation.

Each proposed comparison includes the protected baseline ladder: manual
located transcription; transparent PDF/native-XBRL extraction; tuned pdfplumber
or Arelle in supported format strata; plain Docling; and the same converter
with explicit context/footnote repair. Preserve identical source bytes,
referenced taxonomies, permitted resources, annotation access and tuning caps.
Unsupported formats are a service-coverage status. Their accuracy is unavailable,
not zero. A component score may compare two variants only on an explicitly
identified common diagnostic population; that conditional result cannot replace
the full service population.

The metric request record contains:

| Field group | Required content |
|---|---|
| Identity | Profile ID/version; exact evaluator source/build and dependencies; input bytes and transform hashes; label/adjudication version; task/variant ID |
| Unit and population | Complete package/report/issuer lineage; eligible source-unit and table IDs; full denominator; exclusions and reasons fixed independently of output; PDF/native-XBRL strata |
| Text and geometry | Raw and transformed strings with declared decoding/normalization; scalar/bytes/surrogate policy; declared table extents, spans and occupancy; coordinate frame/page/unit and valid numeric representation |
| Metric semantics | TEDS variant or GriTS content/topology/location definition; text source; single/multi-part table formation; table assignment objective; unmatched/failed parse policy; macro/micro weights and empty convention |
| Bounds and numerical meaning | Feasible selected alignments; fixed versus global assignment scope; estimate versus certified enclosure; precision/reduction/solver version and any checked error guarantee |
| Result and failure | Numeric value only for admitted metric inputs; explicit parse/unsupported/unresolved/budget/numeric statuses; coverage-specific denominator; all original eligible units retained |
| Evidence and decision | Primary context/value/coverage labels; wrong-admitted-assertion veto; diagnostic-only table metrics; independent review status; no transfer of component success into accounting or forecasting acceptance |

TableCell's permissive defaults are adapter hazards: missing text can become
empty text, holes can become unit topology boxes and overlapping cells can
overwrite earlier assignments. The proposed strict adapter checks before those
conversions and before equality shortcuts. It preserves unknown facts in the
evidence store and marks the affected metric unavailable. Embedded NUL, valid
scalar strings and explicit blanks have different meanings from bytes,+surrogates and missing text; no normalization policy is selected here.

Geometry validation needs a common coordinate frame and checks on derived
arithmetic, not just finite endpoints. The retained source's extreme finite
examples can produce NaN or a misleading zero through overflow/underflow.
Nearest float32 rounding also cannot automatically preserve lower/upper bound
direction. The returned multi-table upper sum applies to the lower-selected
assignment; a global exact-assignment upper needs a separate justified bound.
The profile therefore records source metric values as estimates unless a
specific enclosing computation and target scope are supplied.

Keep explicit table-detection, split/merge and multi-page linkage records.
Exact dataset membership, overlap, failure handling and historical evaluator
identity remain unverified for the recent external benchmarks. Published
scores across different populations/text supply/aggregation rules are separate
source results. The unexplained dots.ocr merging difference remains unresolved.
No new model ranking or financial transfer follows from this consolidation.

The primary E1 denominators remain required source units, resolved units,
exact context/value tuples, unresolved units and materially wrong accepted
assertions. Per-report paired comparisons then enter issuer aggregation under
a predeclared weighting objective. The choice between equal issuer and
deployment-volume weighting is unresolved. A perfect table score cannot clear
a wrong admitted unit, entity or time; that material error vetoes the candidate
in the reviewed conformance set. It does not imply a population-wide error rate.

The fictional bookkeeping fixture has four eligible packages with ten required
units each. Two packages have valid diagnostic scores,1 and4/5. One contains
a wrong admitted unit despite its perfect table score; the other leaves two
units unresolved. A parse failure and an unsupported-format package remain
eligible with ten unresolved units each. The exact totals are40 required,
18 resolved,17 correct context/value tuples,one wrong admitted assertion and
22 unresolved. The conditional table-score mean is9/10 on two of four packages.
It is neither17/40 source accuracy nor17/18 resolved-only accuracy. A zero-filled
mean9/20 would silently invent scores for the two unavailable packages.
These are authored accounting-of-results examples, not observed performance.

Stage every per-package metric result and unavailable status before one
idempotent commit. The inspected evaluator updates metrics sequentially and
can leave an earlier metric recorded if a later one fails. A retry must not
double-count earlier successes or silently use different denominators across
metrics. Preserve failure events even where no numeric summary is admitted.

E3 remains separately specified: operating cash flow is the primary target;
cash/debt is a joint secondary vector; first-release outcomes, positive as-of
asset scaling, complete predictive laws, CRPS/energy-score conditions and a
locked same-information/economics comparator remain unchanged. Three questions
remain available: finite-panel description, repeated origins for named issuers,
and prediction over a broader issuer population. Each needs its own substantive
weights and coverage/failure meaning. The user's direction will decide which
question leads; absent that answer, this profile selects none.

All192 exact selected-byte vintage admissions remain false. Publication-event
metadata, ingestion time, label exposure and exact-byte availability are separate.
No E1 table score supplies an historical E3 input cutoff or an untouched holdout.
Population, weights, margin, confidence level, sample size and inference method
remain null. The table-metric source work does not fill those fields. A future
target decision can guide source-theory work while empirical execution stays
held pending its separate prerequisites and authority.

Immediate internal work can proceed independently: prepare source-package
identity/label/failure records, map caller contracts and exact build provenance,
resolve specific vintage routes and preserve proposed accounting-method repairs.
Actual professional review, human acceptance, runtime installation and empirical
campaigns remain distinct later actions. This proposed profile is not a
registered runtime schema, a complete benchmark, or an accepted forecasting
protocol. No whole requirement closes.
