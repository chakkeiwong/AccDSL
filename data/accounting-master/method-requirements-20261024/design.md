# Reusable declared method requirements

24 October 2026. This development reference instantiates the typed predicates
already specified in MethodDefinition. It assesses caller-supplied facts and
findings; it does not execute accounting methods, admit source evidence or
establish accounting authority. The portable definition remains broader.

## Audit and reuse decision

The inspected CompanyOperationsDraft.validate, ReturnModuleAuthoringDraft.assess
and RetainedCompanyProgramDraft.execute contain separate explicit conditions.
The portable exchange builders describe precondition records but do not supply
a compatible common evaluator in the searched paths. Searches of scripts/tests
and accounting-master Python function definitions found no reusable typed
predicate interpreter. This is bounded search evidence, not proof that no such
code exists anywhere. Standard-library Fraction, canonical JSON serialization and the
existing canonical content-hash convention are sufficient for this fragment;
no external solver or package is added.

The prior SQL/null research plan explicitly separates SQL three-valued truth
from entailment over admissible history families. This reference defines its
own finite evaluation tables below. It makes no SQL equivalence, soundness-
approximation theorem or history-family entailment claim.

## Declared inputs and expressions

A manifest contains an identity and version, input declarations, requirements,
capability requirements and explicit residual prerequisites. Each input has a
type, role and source reference. Types are boolean, text, date, or rational;
all carry a caller-declared exact context map. Rationals use reduced n/d strings
with positive denominator. Floats, integer booleans, noncanonical fractions,
non-finite values, unknown fields and undeclared references are invalid.

Values are separately supplied as known(value) or unknown(reason). An omitted
declared input is unresolved with reason missing_input; a structurally missing
manifest declaration is invalid. The literal string unknown is an ordinary text
value, never an unknown sentinel. Supplied input roles distinguish state,
reported_measurement, assumption and caller_finding. They survive assessment;
none establishes factual truth or admission.

The closed expression algebra has ref, const, eq, le, lt, add, sub, all, any and
not. Numeric operations and comparisons require identical types and context
maps. Date ordering requires validated ISO dates and identical contexts. No
implicit unit, currency, entity, book, accounting-basis or measurement conversion
occurs. Boolean combinators may combine propositions about different contexts;
their operand predicates have already been checked. Constants carry explicit
types. There are no calls, imports, arbitrary code, multiplication, quantifiers
or collection traversal in this first fragment.

Known comparisons use exact values. A comparison or arithmetic operation with
an unknown operand remains unknown, including x=x and x-x. This is deliberately
conservative evidence evaluation, not symbolic simplification over a proved
inhabited domain. Repeated references retain the same identity; no independent
draw or probability is introduced. All dependencies, including decisive and
nondecisive branches, are retained. The truth tables are:

| A | B | all(A,B) | any(A,B) |
|---|---|---|---|
| true | true | true | true |
| true | false | false | true |
| true | unknown | unknown | true |
| false | true | false | true |
| false | false | false | false |
| false | unknown | false | unknown |
| unknown | true | unknown | true |
| unknown | false | false | unknown |
| unknown | unknown | unknown | unknown |

not(true)=false, not(false)=true, not(unknown)=unknown. Nonempty all/any avoids
accidental vacuous approval. Size and nesting are bounded as engineering safety
limits, not financial assumptions; oversized requests are rejected explicitly.

## Assessment and immutable selection

The caller supplies a registry keyed by the canonical manifest SHA256 and
selects one exact digest. The interpreter validates the selected definition and
its identity before use. No manifest loads code. Available capabilities are
provided separately by the caller; a missing declared capability is unsupported.

Each requirement has an id, predicate, exact referenced input ids, admission
references, and separate on_false and on_unknown consequences. False may mean
invalid or unsupported; unknown means unresolved. Requirements are all evaluated
before summary: invalid dominates unsupported, which dominates unresolved.
Per-requirement findings are retained even when another finding dominates.
Unknown source/admission judgments must be explicitly supplied as findings and
cannot be inferred from a nonempty source reference or an empty admission list.

A successful summary is requirements_satisfied, with the explicit qualification
selected_requirements_only. Residual prerequisites are always returned. All
outputs retain executed=false, source_admission=false, accounting_admission=false
and method_eligible=false. Full method eligibility requires the remaining source,
schema, domain, authority, state and execution checks outside this reference.

## Comparators and acceptance

Bridge selected original conditions: company-operation tax/floating fractions,
annual coupon, empty initial facility, fee and selected method strings; return
tax bounds, expected/sold units and caller review findings. On otherwise valid
retained fixtures, change one condition at a time and compare with the original
functions. Add conflicting/unknown pairs for the return evaluator, whose
all-condition semantics are explicit. CompanyOperations.validate short-circuits
on global unknowns before some contradictions; do not claim global precedence
equivalence. State that limitation explicitly rather than changing legacy code.

Independent tables, exact fractions, type/context counterexamples, stale hashes,
unused inputs, repeated dependencies and no-mutation checks are primary
conformance evidence. Counts are explanatory. No actual-company applicability,
full compiler, joint feasibility, production readiness or forecast conclusion
follows. A failed bridge triggers repair or a narrower claim; it does not end
the simulator program. S1–S5 remain partial; S6 held and S7 deferred.
