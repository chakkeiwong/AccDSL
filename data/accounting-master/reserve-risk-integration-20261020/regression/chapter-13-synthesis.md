# Chapter 13 — preserving meaning across implementation boundaries

21 October 2026. Version 3.45, physical pages 337–354, viewed and recorded
in order. All chapter nodes have explicit author judgments. This remains

The implementation chapter turns the preceding financial distinctions into
observable software requirements. One transactional store owns committed
journals, economic changes, receipts and branch heads. Analytical files are
derived exports. The initial Python and SQLite choices are justified by
inspectability and scale, not promoted into production-performance claims.
Persistent records retain source bytes, context, time, alternative histories
and review decisions. Duplicate claims and conflicts remain available for
review rather than disappearing behind a database uniqueness constraint.

Exact requests bind arguments, evidence views, settings and expected state.
The business event and the transport request have different identities.
Results retain computational disposition separately from mathematical,
accounting, empirical and human statuses. The incomplete-cash example shows
why reporting only successful paths silently changes a whole-law expectation.
A correction can affect a query through the set of eligible candidates even
when it never selected the corrected record. That dependence must survive
invalidation, while a frozen historical view remains reproducible.

Recovery and migration are equally substantive. Required bytes must exist
before metadata accepts them; checkpoints bind results and explored regions
together. Exact replay compares the same evaluated domain, not whatever two
machines happened to finish before a deadline. Representation-only migration
preserves meaning and old usable records. A choice of storage library or a
documentary trace does not establish crash durability.

The review interface distinguishes source extraction from accounting
acceptance. Correcting an OCR reading differs from an issuer revising the
reported fact. Evidence, model and run identities can therefore change in
different combinations. Stable event keys prevent reposting, and random
coupling does not depend on branch enumeration. The illustrative deterministic
stream is not presented as a validated production Monte Carlo generator.

The adapter material supplies concrete reasons for these contracts. A PDF can
retain hidden text that differs from its visible title. A conversion may
return partial success with no completed page, requested OCR without executed
OCR, or a model name without the weights actually used. Table syntax does not
establish a nonoverlapping rectangular cell partition. A cache pathname need
not identify an existing file, and a successful API return need not be a
validation verdict. These source-derived findings remain distinct from
observed runtime behavior on an issuer filing.

Inline values may already include transformation, scale and sign. Reapplying
those operations changes the amount. Original bytes, assembled text, typed
value and displayed reading consequently retain different fields. Equality
also depends on the question: display equality, typed equality, duplicate
membership and interval consistency are different operations. Pairwise
agreement can coexist with no common value for a whole set. Optional reduced
views retain their members instead of replacing the source occurrences.

The Apple comparison gives these distinctions an actual example. Equal
comparative balances survive different context identifiers; repeated equity
locations cannot be summed. Scale and sign preserve the amount, while
declared accuracy remains distinct from an unrounded economic value. The
selected comparison does not establish whole-filing validation or historical
public availability.

deterministic PDF comparator. Source identity, a resolved environment and

native components and distribution terms retain their own conditions. No
installation or acquired-code execution follows from this reading.
