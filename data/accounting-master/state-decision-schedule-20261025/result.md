# Finite calendars bind decisions when their turn arrives

StateDecisionSchedule/1 accepts one initial book hash and an authored calendar,
then binds each decision to the book produced by earlier successful events.
Explicit dates and integer-day recurrence produce identical execution for the
same dates. Equal-day priorities are explicit; input array order does not choose
economic order. All templates are statically checked before any prefix runs.

Eighteen focused scheduler methods,28 direct decision regression methods and49
exact comparisons across5 cases check complete manually assembled requests,
decision outcomes,current state and every report field. The repeat case sells1
and1/2 units, then does nothing: cash949/2,total inventory65 and selected-lot
carrying5. A zero-reserve case fully disposes the lot and ends with cash482.
Unknown findings stop with the exact successful prefix and pending request.

The calendar tests include leap day, exclusive end, invalid intervals, positive
integer steps, ambiguous same-day ordering, duplicate IDs, stale roots, malformed
future policies, unknown/future information and limits. Limits remain64 total
decisions,32 schedules and inherited2,000,000 bytes/100,000 nodes/depth64.
No monthly roll, business calendar,time zone or endogenous event time is inferred.
