# The existing modules are not interchangeable

24 October 2026. Eight retained references were inspected. Four small original-
context probes pass44 checks over26 protected files. The result is a capability
distinction, not a new company simulation or method ranking.

The return and lease references both derive journal deltas and retain component
memory, but they require different closed state and account registries. Combining
their opening dictionaries would neither create a supported state nor justify
adding component cash or equity. TypedReturnTransition already composes typed
prerequisites, monetary calculations and memory updates for settlement and sale;
that work must be reused. The older boundary's negative Northstar capability
finding is historical, not a description of every later return implementation.

SectorCompany evaluates a report with explicit component mappings and no posting
mutations. Its permitted synthetic entity/currency mapping is narrower than
arbitrary rebinding. HenkelLeaseMeasurements describes conditional measurements
without executable state. Neither result can be used as a native journal module.
The retained SQLite persistence implementation has real transactional code, but
create_run and replay instantiate the older company_execution_v1.Engine. Its
evidence does not establish durability of the newer pure return/lease proposals.

The next smallest useful design is a checked caller envelope that distinguishes
transition proposals from measurement/report evaluation, pins the local method
and schema, preserves complete native results and refuses capability confusion.
It should demonstrate both original return and lease calls without unifying their
books. General shared-state composition remains explicit follow-on work rather
than a claim attached to the wrapper.

No scientific/empirical comparison was run. The original candidates did not fail;
the audit identifies an interface gap and unsupported cross-profile assumptions.
