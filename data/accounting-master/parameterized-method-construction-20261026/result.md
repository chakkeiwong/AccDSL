# Complete methods can be constructed from explicit typed parameters

26 October 2026. MC05/15/17/18/20/24/25/33/34; S2/S3/S4. Four explicit
chart-specific sale/collection templates now instantiate complete methods
through typed named parameters. The constructor imports the retained typed
frontend and schema helpers; it does not import or call native lifecycle
specialization. A check disables native.make_request and still constructs the
same full sale request.

All six retained sale/collection events reproduce their complete native
requests and transition results. Twelve new sequential events across both charts
use new claim keys (slash, tilde, Unicode and code-like text), customers, dates
and amounts, with complete request/result equality. The same templates handle
several live claims and changing state-schema identities. Every emitted method
renders through the existing source grammar and compiles back exactly. All 18
saved constructions and transition results recompute. Twenty-one adverse
controls and 219 assertions pass; all 83 protected files remain unchanged.

The templates retain the full monetary and memory algorithm, not a lookup table
of outcomes. A deliberate collection edit multiplies the requested amount by
one half in all cash, receivable, balance and flow expressions. It produces
exactly half the cash movement and preserves the claim/receivable invariant,
while its complete request differs from the selected native full-payment
contract. algorithm-variant.json preserves both results. It is an authored
alternative, not an admitted substitute under that contract.
