# Event specialization remains partly native

26 October 2026. MC05/15/17/18/20/24/25/33/34; S2/S3/S4. The audit
recomputed both saved complete programs, all 22 commands and 14 full native
event requests, and reproduced the 18 native refusals with exact successful
prefix states. All 78 protected predecessor files remain unchanged.

Complete method bodies, monetary expressions, memory writes, state invariants,
registry selection and program execution already have explicit authoring. The
remaining construction work is real: sale intent chooses claim keys and row
constants; collection selects an owned claim and constructs its pointer and
balance calculation; assessment expands one write group per current claim and
uses date windows and the selected past-due convention. The selected lifecycle
contract currently invokes native make_request for that construction. Naming
and hashing the owner makes the dependency visible but does not make it a
portable declaration. operation-map.json anchors all ten groups to exact source.

Further inspection narrows the gap. MethodMemoryEffects/1 already supports a
dynamic path token from an input pointer, and the v2 typed memory checker accepts
it for a text-typed map key. Reimplementing dynamic paths would be redundant.
However, CompanyBookTransition/2 memory bindings currently take monetary inputs,
calculations or event metadata id/date. They do not directly admit arbitrary
typed full-intent event inputs; collection's dynamic read pointer and assessment's
varying operation population also remain construction-time work. These are
separate requirements, not one missing generic callback interface.

mistaking a parameterized body for a fully portable event contract. The next
unit must label selected native eligibility explicitly and compare complete
requests and effects for consequential new keys/values and both charts. A
substitution mismatch or lost refusal would trigger repair. No empirical
ranking or runtime default is proposed. S1–S5 partial, S6 held, E3 deferred.
