# Declared opening checks

The template is a closed ordered list of structural checks and existing guarded
scalar predicates. It declares each path, equality value, exact schema node,
role/class list, scalar type, report-owner use and command limit. No callback,
Python expression or caller finding is accepted. Selectors are literal record
paths or a balance indexed by an explicitly named role; fixed types and schema
nodes come from the retained chart. No data-dependent stage generation.

Structural operations: exact record fields; scalar text validation; exact scalar
or schema equality; typed book; map-value schema equality; empty map; role
population, injectivity, account classes and cash identity; typed memory leaf;
opening report; bounded command list. Scalar equality/order/positivity uses
MethodRequirements/3 with exact bindings and one active unconditional predicate
per stage. Complete predicate/source compilation precedes evaluation. No stages
are interpreted as accounting or whole-program admission.

Native aggregate record bound and protected dependency checks precede its
body-envelope checks. Dependency pins are captured from the native lifecycle,
typed memory and operating-method owner, while execution calls only the retained
typed/report/requirement libraries. The operating builder's returned methods are
unused by native validate, so its declarations are not rebuilt as fake work.
At an empty admitted claim map, the invariant step is exactly zero receivables;
the nonempty row invariants have no admitted rows. Every later execution still
uses the complete authored invariant.

Call identity binds the complete template and native-shaped input, plus the
input serialization (including nested map insertion order). Canonical hashes
alone ignore order that may affect the first validation error. No outcome or
passing certificate can replace evaluation. Return accepted/rejected stage,
native reason, predicate/report evidence and no posting. Native validate is
only the comparator, disabled together with native control/claim_type and the
operating builder during candidate checks. Full input bytes and templates
remain immutable. Missing template conditions would define a weaker selected
contract; selected-template identity is therefore explicit and consequential
edits are never described as native-equivalent.

Initial evidence and diagnostic roles follow the phase plan. Preserve all 58
audit inputs including future malformed/unknown commands accepted by native
opening validate. New tests distinguish metadata, map schema, empty population,
role/unit-cost/report conditions, stale selection and changed rules. No future
command structure is prevalidated by this opening evaluator.
