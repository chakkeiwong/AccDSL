
\paragraph{Run the selected commands as one program.}
An ordered program must preserve more than the last balance. Suppose a
receivable's due date is extended twice, a partial receipt follows, and the
unpaid balance crosses a year-end. A rejected later request must leave the
earlier extensions, assessments and receipts intact. Reconstructing the input
from a convenient stored snapshot, or recomputing a selection from changed
source, would conceal a different history.

\code{SelectedTermProgram/1} therefore supplies the complete state-contract
source, the four event/carry rule sources, an opening state, a declared supplied
population and an ordered list of complete requests. An independently supplied
selection binds the exact source bytes, program contents and declaration order.
Every request retains its own expected-state identity. The program derives
transport calls only after those identities agree; it neither authorizes a
new selection nor rewrites a stale request to match the current state.

Compilation checks the whole source envelope before execution. Each successful
command then passes its full state and returned population coverage to the next
command. A first-command refusal returns no successful prefix; a later refusal
returns the complete successful prefix, unchanged last accepted state and
coverage, the failed request and result, and the untouched remaining requests.
Unknown approval remains unresolved. A partial supplied population does not
become complete because some commands can be evaluated. The program performs
no durable commit.

The two retained ten-command programs reproduce every field of the earlier
source executions, including period carry and its complete report result.
Both end with cash 130 and receivables zero. More revealingly, the old February
assessment retains overdue 20 under the initial January due date after both
extensions. March's zero assessment remains tied to the first extension;
the April and June assessments use the second. A receipt changes the amount
outstanding but does not retrospectively change an assessment. A new assessment
records zero after the next year's final receipt.

Fifteen adverse cases exercise changed source, opening and command order,
unknown approval, partial population, malformed declarations and later failed
requests. A relocated copy also recomputes both complete results with identical
canonical and insertion-order identities while native financial builders are
disabled. These checks make the selected program reproducible; they do not
make it a general company grammar. Standalone arbitrary report commands,
cross-profile migration, actual historical completeness and accounting
applicability remain separate requirements. The profile caps a program at
64 commands, and inherited structural limits can refuse a smaller instance;
neither limit is an economic capacity claim.
