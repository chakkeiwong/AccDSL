# OTSL source inquiry: local syntax is insufficient for cell geometry

12 October 2026. **50 checks pass**. Seven resources were retained, including
the publisher's HTML response to the PDF route, the exact arXiv v1 PDF and a
Git-blob-verified 4.0.2 token-conversion source. All fourteen PDF pages and ten
selected renders were read. Twenty-three reference entries have dispositions.
The archived Docling report supplies an inspected forward citation. No
systematic citing-work coverage, published-full-text equivalence, model run or
local performance comparison is claimed.

The source's five-token language offers compact table representation and
backward-looking conditions. Its six printed rules accept `C L NL / U C NL`,
but the declared directional merge meanings join three corners of a 2×2 grid
into an L-shaped cell. The rules are therefore insufficient for the stronger
claim of a nonoverlapping rectangular-cell partition. The deterministic
diagnostic verifies every rule, the merged occupancy and four control cases.
The paper itself distinguishes syntactic validity from a correct prediction.
`technical-review.md` reconstructs that argument before identifying this
precise limitation; the method as a whole remains viable with extra checks.

The retained consumer has a separate source defect: `line_num` is assigned
zero once and never updated, so a correction described as first-line-only
rewrites raw xcel on later rows too. The inspected HTML helper checks row
lengths and expands spans without establishing full merged-cell occupancy.
These are static source conclusions, not observed report-level failure rates.
The candidate's experiment/checkpoint identity and complete runtime remain
unverified. The source inquiry triggers a specification repair, not an
unauthorized code change or model campaign.
