This document specifies a system that translates company disclosures into traceable evidence,
represents several compatible economic and accounting histories, and simulates their future
journals and financial statements under explicit economic scenarios.
The proposed data contracts, methods and acceptance cases specify the intended implementation.
Current source and domain limitations remain explicit; this candidate is not a completed product
or a claim of full proposal readiness. Proposed libraries can be replaced while preserving those
contracts. Sector rule packages require their own accounting review before they can be described
as compliant with a reporting standard.
Research materials, source qualifications and review records accompany this document in
docs/design/research and docs/design/review.

The checked partial calculation binds each result to the original request, declaration, domain,
methods and temporal frontier. It retains the supporting branches, unresolved source outcomes
and pending temporal domains. Changing a message, source, actor or domain cannot reuse the
old result as the answer to the new question. A future extension rule may justify some reuse,
but that relation must itself be stated and checked.11
This construction joins a fixed decision problem to an unfinished search without treating
uncertainty as missing arithmetic. Longer horizons, additional actions, changing declarations
and broader observation languages still require their own comparisons.
17.22
Changing a message without confusing the decision prob-
lem
A manager may receive a differently worded notice carrying the same information, or a notice
that distinguishes two situations previously described alike. These changes have different
consequences for a policy. The preceding requirement to fix message meaning does not prohibit
either change. It requires the simulator to state which relation connects the old decision problem
to the new one, and to identify the new result accordingly.
A consistent one-to-one renaming preserves the original distinction between every pair of
messages. The finite comparison checks that renaming across every raw observation in every
original source head, including heads not selected at the current frontier. It also preserves actor,
decision dates, action meanings, source identities and second-stage memory of the manager’s first
action. Each total rule then has exactly one renamed counterpart. The first- and second-action
refusal conditions have the same truth values after the key positions are permuted, so the full
surviving rule sets correspond exactly. This is the same finite decision problem under different
spellings; it is not an expansion of what the manager knows.

17.22.1
A refined notice allows the old distinction to be recovered
Now suppose a correction distinguishes a low message that was previously shared with another
source history. The new message identifies which of those situations occurred. A manager can
ignore that distinction and follow the old rule, or potentially act differently in the two situations.
To make this precise, each refined message must map to one old message, consistently across all
original raw observations. Combining this message map with the unchanged decision stage and
own-action memory gives a map from new policy keys to old keys.
Write Uo and Un for the old and new finite key domains, and e : Un →Uo for this erasure map.
Require e to reach every old key. An old rule πo assigns pay or draw to each old key. Its lifted
rule Leπo chooses πo(e(u)) at a new key u: the manager acts as if the additional distinction
had not been received. New keys that erase to the same old key form a fiber. A rule constant
on each fiber makes the same choice at all of those keys.
For the same checked temporal frontier, let Co and Cn be the rules satisfying the old and
new known constraints. The comparison preserves each underlying action row and its refusal
meaning, and checks that erasing the new forbidden assignments gives exactly the old forbidden
assignments. Under those conditions,
{Leπo : πo ∈Co} = {πn ∈Cn : πn(u) = πn(v) whenever e(u) = e(v)}.
(17.35)
To see the first direction, a lifted rule makes the old choice at each corresponding raw observation.
A refused first action or refused pair of successive actions would therefore also have been refused
under the old rule. Conversely, a new rule constant on fibers defines a unique old rule because
every old key has a preimage. The same correspondence of refused assignments then shows
that this old rule satisfies the old constraints. The relation concerns exact finite rule sets under
supplied message semantics; it assigns neither probabilities nor monetary values to information.
17.22.2
Additional rule assignments need a reached-action comparison
In the correction-specific low-message example, the old declaration permits four total rules
and the refined declaration permits eight. Lifting preserves all four old rules. The other four
also produce distinct sets of reached action rows across the complete selected family. Here the
new distinction therefore permits additional feasible behavior under the stipulated information
design. In another example, collapsing the first messages leaves no feasible rule, while restoring
the refined messages permits four. Neither comparison establishes that those messages are
actually available to a real manager or that any policy maximises value.
The source-unknown examples show why counting total rules is insufficient. With conflicting
source heads, a refinement increases the unconstrained assignments from 32 to 2,048, but there
is no selected history on which to demonstrate a new action. Every rule has the same empty
reached-row signature. Under inconsistent clocks, the corresponding counts are 32 and 512,
yet no admissible time assignment exists. An empty signature is a set used for comparison,
not a realised or feasible company behavior. With unknown access, additional choices can be
exhibited on the selected completed histories while the overall source family remains unresolved.
The comparison therefore retains both the full rule sets and their reached-row signatures. Pending
branches, unknown source outcomes and inconsistent clocks keep their original meanings. The
refined result has its own declaration and domain identity, even when its feasible rules correspond
exactly to an older result.12
