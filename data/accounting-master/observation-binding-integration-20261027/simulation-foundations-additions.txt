17.18.4
What a complete conditional answer must retain
The original coarse/refined correction example remains different from the swapped-encoding
example. The coarse member already has no feasible policy. Identifying that member does not
supply the refined signal it lacks. The joint policy problem therefore stays infeasible even if the
actor is told which mechanism applies. An unresolved source outcome for which no observation
map is specified instead leaves the policy question unresolved; it is not another zero-policy
result.
The checked finite method retains the full financial population for every mechanism and solves the
shared-history constraints in two ways: enumeration of feasible instructions and an independent
formulation of forbidden action combinations. It also compares the complete policy sets with
explicit relabelings of the original policies. The checks distinguish a missing action row from an
available safe action, and preserve the original temporal supports when equal numerical answers
share storage.
These results explain how unresolved uncertainty can persist without requiring a separate
explicit node for every time or transaction possibility. Symbolic temporal restrictions represent
many possible times; shared numerical results avoid repeated calculation; common histories
impose the information limits on decisions. Each operation preserves a different relation and
needs its own justification. General observation languages, longer horizons, empirical actor
access, saved partial frontiers and durable recovery require further work.8
17.19
A visible label need not identify the observation mecha-
nism
In the preceding example, a first message H requires pay under one interpretation and draw under
another. An additional label can resolve the conflict if it tells the actor which interpretation
applies. Suppose, however, that both interpretations attach the same label, reviewed, to that
message. The actor sees a label but still cannot distinguish the two cases. Declaring a label
visible and declaring a mechanism identified are different assumptions.
The distinction changes the feasible policy set. With distinct labels supplied before the first
decision, the two four-policy problems admit 16 joint policies. With the same label supplied in
both, the conflicting instructions remain and no common policy is feasible. A simulator that
automatically inserts its internal mechanism identifier into the actor’s message would report
the first answer while pretending to solve the second problem.
The selected observation declaration therefore records the actual token presented to the actor.
It permits distinct mechanisms to emit the same token. Source identities and temporal proof
labels remain attached to the analyst’s explanation, but do not enter the decision history unless
the declaration supplies a separate observation with that meaning. The numerical comparison
keeps these cases apart even though both could informally be described as a labeled source.

17.19.1
A message map must use information available at that date
Hiding internal identifiers is insufficient if the message itself encodes an unavailable fact. A
map that takes the entire financial history as its input could send one message when a hidden
borrowing right exists and another when it does not. The resulting policy would exploit that
right even if the source observations never revealed it. Giving the message an innocuous name
would not remove the additional information.
The finite reference avoids that ambiguity by restricting what each map can read. At the first
date, the coarse view supplies the market signal; the refined view supplies that signal and the
current coupon-trigger observation. At the second date, the map receives the already specified
trigger and cash-coverage observations. The actor retains the first message and its own earlier
instruction. Hidden contractual rights, complete world identifiers and later observations cannot
be introduced as new first-date map inputs.
For each selected source outcome, the declaration must map every supported observation
key to a message. A missing key is an unfinished declaration, not permission to remove the
corresponding financial history. Two entries for the same key are also invalid. These restrictions
establish a closed finite interpretation of the existing observations. They do not establish that
those observations describe a particular company’s actual information practices, nor do they
define a general language for arbitrary messages.
This ordering is useful when designing richer models. First specify which quantities can be
observed and when; then specify how the observation is represented to the actor; finally constrain
decisions to agree on indistinguishable histories. Reversing the order can make a desirable
policy feasible by designing messages around the hidden state that policy would need to know.
17.19.2
Source, actor and time remain separate premises
A claimed visible tag carries an actor, the selected source revision, its content identity, a token
and an observation time. The first decision must agree exactly with the temporal family’s cutoff;
the second occurs strictly later. A tag claimed at the first decision must have been available by
that instant. Equivalent fixed-offset spellings describe the same instant, whereas a tag received
one ten-millionth of a second afterward is late under the selected exact-time convention.
Unknown tag availability leaves the declaration unresolved. So does a supplied observation
whose chronology cannot be established from the retained authorship bounds. The current
reference treats this conservatively: it does not discard inconvenient clock possibilities or silently
refine the source family with a new tag observation. A later method may condition or refine
that family under explicitly admitted additional evidence, but it must preserve the distinction
between the original question and the revised one.
These unresolved cases differ from a complete observation model with no feasible policy. In
the latter, the available histories are specified and every possible instruction fails somewhere
in the retained financial family. In the former, the model has not established which histories
the actor may distinguish. Returning the same empty policy list for both would hide a missing
information premise behind an apparently decisive financial conclusion.
A content identity detects alteration relative to expected bytes; it does not show that the actor
received them. Likewise, the synthetic tag records used in the comparison test the consequences
of supplied assumptions. They are not observations of a real company’s managers or investors.
That distinction remains necessary even when every mapping and timestamp check passes.

17.19.3
Reuse the calculation only when the decision problem is unchanged
A corrected source can preserve the same financial meaning and messages. The numerical policy
calculation can then be reused while its source explanation changes. A different actor can also
have the same supplied observation map; the actor binding must change even if the resulting
mathematical problem is identical. Neither case licenses removal of the old and new source
supports from the retained temporal family.
Changing a message label is different. A policy is a rule for responding to the labels the actor
receives. Relabeling H as another token changes that rule’s interface even if four policies remain
feasible and a mathematician can construct a one-to-one relabeling between the sets. The
selected reference recomputes this case. It does not claim to have proved and implemented a
general translation between equivalent policy representations.
The reuse comparison consequently includes the complete financial and action population, the
actual first and second messages, the meanings of the actions, and the numerical methods.
Identical repeated constraints can share computation while keeping every source outcome and
temporal proof support attached. Distinct problems with zero feasible policies retain distinct
identities. A future correction that is unavailable at the earlier cutoff remains in the source
record without replacing the earlier view.
The independent checks reconstruct the messages from the supplied declarations and original
observations, compare full policy sets from two formulations, and reject missing or duplicated
keys, hidden-state inputs, wrong actors or times, altered sources and forged prior results. They
also check changed second-date labels without changing first-date messages. These examples
make the dependency rule concrete: identical counts are not enough, but a changed source
explanation need not force an unchanged numerical problem to be solved again.
The remaining computational difficulty is how to continue an unfinished temporal search
while retaining its unexamined possibilities. The conservative full-domain remainder already
prevents a partial result from masquerading as complete; a checked, resumable partition would
additionally preserve useful completed work. Actual message provenance, richer observation
languages and refinement by new tag evidence remain distinct extensions.9
17.20
Stopping a search without losing the possibilities it has
not examined
A correction may have reached the manager before a payment decision, or afterward. An interval
for the delivery time can preserve both possibilities without assigning either a probability. If
the source record contains several corrections, public releases and private deliveries, the exact
temporal calculation may exhaust its work allowance before checking every combination. The
unfinished calculation still has a useful result, provided it keeps the completed conclusions
together with an exact description of what remains unexamined.
The conservative earlier method returned the whole original clock domain whenever its search
stopped. That answer preserved uncertainty but discarded useful completed proof work. A
resumable calculation can retain more. It must save the partition it has already established,
including every unfinished part. Saving only the branches that produced interesting financial
views would change the question on the next run.

The search resolves one pending cell at a time. It first checks whether the cell is empty. A
nonempty cell with no remaining revision to classify yields a selected or unresolved source view.
Otherwise it installs the complete family of children above. Only after all those children exist
may the calculation pause. This logical rule prevents a work limit from turning a complete split
into a partial list of favorable branches.
17.20.2
Pending does not mean feasible, and known does not mean complete
A saved node has one of four meanings: its domain remains unchecked; a contradiction proves
it empty; a witness establishes a terminal source view; or a witness supports an expanded cell
whose children form the complete partition. An unchecked child need not contain a possible
time assignment. It may already be inconsistent with an earlier chronology restriction, but
the calculation has not yet established that. Retaining it is conservative; deleting it without
checking is unsupported.
In the selected example, resolving the root installs eight children. Seven are later proved empty.
With a one-node work allowance, all eight remain explicitly pending. The result therefore neither
asserts eight feasible worlds nor pretends that the single eventual view is already established.
The eight cells are a representation of unresolved work under known restrictions.
Once some terminal views are known, they can be displayed together with their source supports.
Agreement among them still does not establish that the whole family has that view. An
unexamined cell could contain a conflicting correction, a retraction or a different access history.
Completion requires that no pending cell remains, including cells that eventually prove empty.
The same distinction controls policy interpretation. A policy that fails in an already established
view fails for any larger family containing that view. A policy that succeeds in every established

17.20.3
Resume the original question and preserve its proofs
The checkpoint binds the complete source request, actor, trust declarations, timing assumptions,
method identities and execution allowance. On reading it, a separate checker reconstructs each
branch’s constraints from the original domain and its path. It does not accept a saved mutable
constraint list as a substitute. It verifies all completed witnesses or contradictions, the exact
complement structure, source outcomes, support paths and work counts.
The reference uses a fixed left-first depth-first order. This makes the resumed tree directly
comparable with the existing uninterrupted calculation. It also allows the checker to reject a
purported completed branch placed after an earlier unfinished one. The order is a comparison
convention, not a claim that this schedule is the fastest way to find useful financial conclusions.
A step allowance specifies how much new work one call may perform. A separately bound total
execution cap determines when further work must stop. Reaching that cap retains the pending
tree and reports a capped calculation; it does not turn unresolved cells into completed results.
The test with a cap of two preserves the same original question and performs no repeated
solver work when resumed at that cap. Changing the cap or the source assumptions requires an
explicitly different, checked request to the continuation interface.
Across the 47 selected temporal requests, step allowances of one, two, seven and 4,096 produce
exactly the same final proof trees, outcomes and source supports as uninterrupted search. Earlier
certificates remain unchanged at every pause. A separate reread checks 1,060 saved checkpoints
and rejects altered partition cells, proofs, source premises and completion declarations. These
comparisons establish the selected finite continuation property.10
This representation avoids a separate explicit node for every real-valued event-time assignment.
It does not remove exponential growth in the number of distinguishable revision combinations.
Nor does installing all children before a logical pause establish crash-safe file storage, authenti-
cated evidence or actual actor knowledge. Larger revision families, better schedules, justified
approximate reduction and durable storage require their own arguments and comparisons. The
useful advance here is narrower: unfinished computation retains both what has been proved
and every domain that has yet to be checked.
