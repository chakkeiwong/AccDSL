The accompanying SuppliedClaimPopulation/1 declaration states whether the supplied internal
claim map is complete, partial or unknown. It names /claims, identifies the exact opening book
and supplies provenance. Only an explicit complete declaration proceeds under this profile;
partial and unknown declarations return unresolved before any command runs. Completeness
here concerns the supplied internal state. A populated map, a balanced book and a successful
continuation cannot establish that a real issuer has disclosed every claim. That different question
still belongs to source-constrained reconstruction.
Admission first runs the retained structural and opening-report checks on the same input.
It then evaluates the full selected invariant over the unchanged book, schemas and memory
definition. The invariant checks the aggregate receivables relationship and the claim conditions
that the simple relaxation missed. A malformed schema or incomplete statement mapping
therefore still fails its original check. A mid-period snapshot also remains unsuitable as a
new-period opening even if its claims satisfy the invariant. This profile deliberately checks
structure and the opening report before the full invariant; it does not promise an older profile’s
failure precedence when several conditions fail together.
The program wrapper, AdmittedCompleteClaimsProgram/1, retains the complete admission result.
After admission succeeds, it delegates to the existing opening-to-program binding using the
derived structural template and its corresponding internal selection. That binding again checks
shared facts, schemas, mapping, memory definition, roles, policy, rules, invariant, complete
projected commands and event-input order before the unchanged composer runs. A caller-
supplied success flag cannot replace these checks. The retained delegated result exposes the
requests, transitions, reports, carry state, trace and any stopped suffix.
