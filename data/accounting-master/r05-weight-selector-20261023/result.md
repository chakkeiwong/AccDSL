# Predictive weight and selector design result

This bounded design unit specifies a candidate forecast-combination and fixed-
selector procedure for E3. It does not fit a named company, admit a historical
vintage, or run a forecast. The current source evidence supports the need for a
semantic duplicate policy and timing discipline, but not a Bayesian prior,
likelihood, cross-origin feature map, future origin grid, or inference law.

The proposed candidate first quotients duplicate encodings into canonical
semantic components. It then learns a versioned feature-based score map and
simplex combination coefficients from earlier eligible origins using the same
asset-scaled CRPS objective. The coefficients are predictive-combination
weights, not probabilities that histories are true. The fixed comparator uses a
separately frozen feature-based selector on the same earlier-origin data and
budget. Lexicographic semantic IDs resolve exact substantive ties only. Missing
law, missing alignment, late labels, missing scales and service failures remain
invalid rows; no mass or company is dropped and no remaining weights are
renormalised.

The exact standard-library reference tests a persistent two-component fixture.
The grid fit selects weight one half with mean CRPS one half; the selector's
exact tie chooses `a_history_zero`. Absolute-distance and independent CDF
integration agree. Splitting one canonical component into duplicate encodings
leaves the mixture unchanged. Negative weights, missing components, late labels
and invalid laws are refused. These checks validate bookkeeping and a finite
objective only.

## Pre-mortem and red team

The run could appear successful while learning a representation-specific rule if
canonical IDs or features change with later evidence. It could fail because the
annual panel cannot supply enough strict pre-start origins rather than because
history preservation is unhelpful. The cheapest discriminator is a versioned
cross-origin feature-map audit with every input availability and component
identity recorded. The strongest alternative explanation for a future gain is
better generic forecast combination or unequal fitting information, not the
history-preservation operation. A gain would be overturned as a mechanism claim
by an unmatched input, a target change, or an after-outcome selector. The weak
point is transport of a development feature map to future accounting regimes.

No whole requirement closes. All 192 historical-vintage admissions remain
false, and the manuscript remains Version 3.48 / 401 pages / `not_ready`.
