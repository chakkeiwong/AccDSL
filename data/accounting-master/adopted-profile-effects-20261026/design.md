# Adopted-profile reader audit

26 October 2026. The plan passes with explicit source-locked provider additions.
Inspected the full Descriptor and composition Library/assess methods, both
successor auditors, insurer complete packet and exact-bank packet/schema shapes.

Three actual interface mismatches require repair. The old insurer descriptor
requires exactly six world fields and reconstructs a slash key; the adopted
policy adds identity_profile_ref and uses an encoded pair. The bank successor
intentionally mixes new request/result/profile schemas with an unchanged native
Submission schema; deriving every schema from one prefix is therefore wrong.
Finally, composition's financial-profile equality alone does not express the
insurer execution-policy difference, although its complete-world comparison
currently refuses the mismatched worlds.

Preserve all old readers and 77 exact text/typed results. Add pinned provider
readers for the actual checked packets. Reuse the complete descriptor body with
only schema lookups changed to an exact per-kind schema map; retain that delta
for inspection. A successor wrapper supplies its explicit seven-field insurer
world and pair-key rule, runs its native validity checker, and includes the
immutable policy/profile/source bindings in PublicationEffects/2. Bank checks
retain exact-time validity and mixed schema IDs; it has no financial effects.

Composition uses the old grammar and evaluator with one explicit execution-policy
comparison before complete-world matching. A financial-profile mismatch keeps
the existing cross-profile refusal. A policy mismatch receives a separate
unsupported finding. Native legacy stages have no extra policy binding; the
insurer successor does. Duplicate financial publication identity remains keyed
by financial profile and request pair: migration does not authorize a second
posting in a new policy namespace.

Each packet's source hash, whole-file dependency lock and native policy checks
are validated before providing descriptions. Mutable imported module names in
the two historic auditors are isolated while loading so their different
financial_checks/source_policy modules cannot be confused. Full native and
derived effects are compared; no helper filename implies semantic equivalence.

All original protected packets and manuscript sources stay unchanged. New
documentation remains provisional. Counts are explanatory, not promotion;
missing native validation, lost policy, hidden financial effects, changed
unknown propagation or changed old text/typed result veto the candidate.
This does not supply an InsuranceComponents-to-InsuranceAssessment state adapter.

Packet inventory finding: the insurer verification packet retains several
recovery examples under the same display label. Its list entries are unambiguous,
but turning that list into a map by label would overwrite examples. Provider
imports therefore use the exact source hash plus a stable ordinal-qualified
identifier; the original label remains explanatory metadata. The provider does
not rewrite or pretend uniqueness of those frozen labels. Bank records are read
lazily with one current native auditor so the 63 source packages do not multiply
large base registries in memory.
