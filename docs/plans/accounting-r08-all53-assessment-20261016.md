# R08 all-53 assessment and first implementation slice

16 October 2026. Candidate Version 3.14, 349 pages; full mission remains
**not_ready**. This plan addresses MC01–MC35/G1–G18 and depends on the current
P5, R04 and R06 evidence. It is an assessment and staging unit, not a runtime
launch.

## Skeptical audit and evidence contract

The question is whether the exact current candidate supplies the original
design obligations and a concrete first implementation slice while preserving
the unresolved boundaries. The baseline is the 53-record evidence ledger plus
all successor reconciliations. A finite check count, clean PDF, source hash,
or author review is not a promotion criterion for full readiness. Missing
authority, actual facts, whole-package semantics, independent review or human
understanding are explicit negative evidence for the affected row.

Primary criterion: each of the 53 rows receives a current evidence pointer,
scope judgment, residual category, dependency and next action, and every
interaction that could change that judgment is classified. Promotion requires
no unresolved consequential design choice and the independent review status;
one row's finite packet cannot promote another. Hard vetoes are corrupt or
unbound candidate bytes, missing required evidence for a claimed method,
contradictory contracts, or an interaction with unexplained state. Descriptive
diagnostics are page counts, check counts, ledger sizes and clean-build status.
No readiness, implementation conformance, accounting compliance, forecast
validity, distribution clearance or human acceptance is inferred here.

## Interaction checks

1. Source correction -> history family, query information set, journals and
   dependent forecast; retain unaffected views and unsupported mass.
2. Annual/interim/revised availability -> permitted scenario knowledge and
   report dates; missing publication blocks only the affected as-of claim.
3. Financing/group/FX event -> perimeter, currency, journal, state and cash-flow
   boundaries; no unexplained residual transaction or double elimination.
4. Bank/insurance extension -> common state, authority and failure contracts,
   while keeping prudential weights, cohorts and service/finance components.
5. Aggregation/search/adapter loss -> explicit answer guarantees and unresolved
   status; no silent renormalisation.
6. Ownership/tax/elimination -> legal books, group worksheet, NCI and origin of
   tax effects; no current-period plug or ending-percentage shortcut.

## First implementation slice

After the execution hold is lifted, begin with the already specified finite
Core 0 plus the exact P5 company case: retained source/value records, typed
opening/event/history view, two legal books and group worksheet, one joined
return/debt/inventory/tax/ownership close, three report projections, refusal of
unsupported migration, and request identity/replay/lost-ack behavior. Inputs,
expected outputs and adverse cases are the preserved P5 exchange packet; this
selection is a staging boundary, not a reduced mission. Next dependencies are
source lowering and shared IR, real-package partial answers, wider corporate
and financing methods, bank and insurance adapters, selected XBRL/PDF inputs,
and target-specific forecast protocols.
