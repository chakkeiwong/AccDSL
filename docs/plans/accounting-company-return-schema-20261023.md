# Native return schema and matched authoring conformance

S3/S4; MC08/10/13/18/24/25/28/34. Governing design is the checked specification
under company-native-return-design-20261023 and its protected manuscript
integration. The next task is a closed, explicitly versioned authoring/state
contract; it is not permission to replace the legacy engine wholesale.

Question: can typed and text authors describe return component memory,
recovered lots, source findings, tax bases and settlement/sale events without
losing owner, amount or information identity? The baseline is the protected
P legal-book trace and the current six company scenarios. Primary pass
criterion is exact text-to-typed round trip, full field/dependency validation
and an unambiguous event-to-method binding. A parsed record alone cannot claim
native accounting execution or full-year conformance.

Skeptical audit: the 29-line report, homogeneous stock identity, fixed account
list and immediate-deductible tax path are incompatible with a silent field
addition. Create a new closed draft profile and explicit legacy selection.
Preserve old bytes and results. A module state is an allocation of one shared
book, not a separately funded subcompany. Required facts must remain unknown
when absent; Boolean false differs from unknown. Exact rational and context
checks precede method selection. Tax state cannot disappear after parsing.

Implement one schema and one text grammar for component/lot/tax declarations,
versioned account roles and dated settlement/whole-lot-sale events. Bind every
method to its selected profile and source premises. Test missing/extra fields,
bad units/owners, duplicate identities, wrong tax bases, value/carry mismatches,
invalid chronology, normalization changes and malformed findings. Preserve a
matched retained example, negative cases and read-only replay. No arbitrary
code invocation, whole-tax default, group-owner change or forecast inference.

Then extend the smallest reference execution path under a separate audited
plan: shared journal proposals -> exact account/memory updates -> tax close ->
annual reports -> next-year carry. Use the already checked retained method and
legal-book comparator. Keep old scenarios in unchanged legacy mode, and test
the entire new trace rather than only final totals. Unsupported tax, partial
lot disposal and source admission stay explicit until their methods exist.

Default audit: the selected return case is a finite baseline, exact arithmetic
is a compatibility choice, text syntax is a replaceable engineering design,
and account/tax role names are not new accounting authority. A schema that
passes while omitting a required dependency vetoes promotion and triggers
repair. Only lost indispensable comparator/source bytes or an unresolved
material domain choice blocks its dependent step. Missing human acceptance
does not stop authorized provisional internal design.

Save artifacts under data/accounting-master/company-return-schema-20261023.
