# Schedule decisions without precomputing future company states

25 October2026. S2–S4; MC13/14/15/18/23–26/28/32/34/35.

## Question and evidence contract

Can a reusable authored decision rule run on a finite calendar while reading
the book produced by the preceding successful event? StateDecisionEvent/1's
sequence requires an expected state hash for every request. Its example builds
later requests by executing earlier decisions first. That is useful evidence
but an incomplete simulation-authoring interface.

The candidate binds one initial book hash and explicit authored schedules, then
creates each request only at its scheduled turn. Dates are either supplied
explicitly or generated from a start, exclusive end and positive number of
calendar days. This is calendar arithmetic, not endogenous event discovery.
Equal-date decisions require explicit unique ordering; no implicit lexical
priority. Stable decision/event identities derive from declared schedule IDs and
occurrence numbers without interpreting untrusted text as code.

Comparator: the unchanged checked StateDecisionEvent/1 sequence, manually
materialized for the same dates and policy. Primary criteria: exact requests,
proposals, complete states, native transitions and financial statement fields;
independent remaining-stock arithmetic; no-action cursor and refused-prefix
preservation. Duplicate identities, ambiguous order, stale initial state,
invalid/future information, invalid calendars and changed pinned source veto
the candidate. Counts and runtime are explanatory only. No actual behavior,
forecast skill, general schedule completeness or physical durability follows.

## Skeptical/default audit

Do not silently use365-day years, business-day conventions, month-end rolls,
timezone conversion or borrowed ACTUS semantics. Only explicit calendar dates
and integer-day steps are supported; monthly/contract calendars remain open.
The existing authored-closed-path premise means there are no omitted external
events. A schedule hash binds that assumption, not source truth. The selected
lot and typed program remain fixed; state inputs bind afresh at each occurrence.
Use the unchanged decision runtime rather than copy native accounting rules.

Convenience limits:64 generated decisions,32 schedules and a bounded request
byte size; these are hypotheses about a tractable reference, not throughput
claims. Validate all calendars/ordering and declared templates before running a
prefix, so a malformed future entry cannot be hidden by an earlier refusal.
Stop at the first unresolved/refused decision, retaining the pending calendar
and current book. No automatic repair or alternate policy is invented.
