# Bind common method inputs without conflating eligibility and execution

26 October 2026. S2/S3/S4; MC02/06/20/24/25/33/34, G2/G12/G18 and I04.

Question: what additional contract is required to connect the existing versioned
method-requirement evaluator, exact input binder and authoring forms to a native
financial invocation? RetainedProfileComposition/1 only describes existing
exchanges; it cannot be promoted into general method-input authoring.

Skeptical audit: avoid another independent predicate interpreter or a wrapper
that declares requirements_satisfied to mean eligible. Baselines are the actual
MethodInputBinding/2 and MethodRequirements/1–3 behavior, current portable
MethodDefinition, and one selected native request/response contract. Compare
full context, source/assumption role, information timing, ownership and exact
profile/signature bindings. No automatic dispatch, callbacks or new accounting
rule. Start with the smallest real missing binding found in those interfaces.

Primary criterion: a written field-level mapping and matched positive/negative
examples show what may be carried unchanged, what requires explicit evidence,
and which unknowns/capabilities prevent invocation. Wrong context/role/schema or
stale digest must refuse; selected requirements cannot conceal residual source,
authority, state or execution obligations. Compile-only evidence must never
imply posting or actual-company admission. Counts are explanatory only.

1. Read exact local evaluator/binder/portable definition contracts and one native
   signature. Record the missing link and reuse decision before implementation.
2. Add only a bounded typed/text binding if the inspected contract justifies it;
   otherwise make the specification gap and its required fields concrete.
3. Compare with existing evaluator findings and native request bindings,
   including incompatible context, unknown premises and unavailable capability.
4. Record results, update the current program, and continue the next unresolved
   design obligation. Broader authority/source questions remain separate.
