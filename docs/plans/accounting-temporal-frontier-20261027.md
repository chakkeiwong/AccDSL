# Preserve and resume a complete temporal proof frontier

27 October2026. MC01/03/05/11/12/13/24/25/26/28/33/34;
W01/03/04/11/12/16. Design reference, product implementation held.

Question: can bounded temporal search resume without losing unexamined clock
assignments, recounting completed views as exhaustive, or merging source supports?
Baseline: ExactSourceTimeViews/1 and BoundTemporalPolicyFamily/1. The old budget
stop discards its partial tree; the current binding conservatively retains the
whole original domain and no completed policies. Preserve both accepted writers.

Specify a successor proof partition whose nodes are checked empty, checked
nonempty terminal, expanded complementary split, or explicit pending domain.
Every original timing assignment belongs to a terminal or pending region; all
first-failure complements remain present. A paused frontier has known outcomes
plus an unresolved remainder, never a complete family merely because completed
leaves agree. Bounds, source identities, actor/trust, original precision and
chronology semantics belong to the externally expected request and checkpoint.

Use a fixed traversal and exact original-edge certificates. Resume only after a
checker reconstructs every path and validates all completed/pending domains,
partition shape and budget accounting. Duplicate pending/terminal nodes, missing
siblings, edited constraints, changed requests, stale certificates and altered
method versions refuse. A matching internal hash is not external authorization.
A valid empty pending region may be closed by a new proof; it must not disappear
without that proof. Do not claim crash-safe storage from in-memory transport.

Primary criterion: complete resumed families equal the existing uninterrupted
exact families on all selected requests, including full outcomes and source leaf
supports. An independent frontier checker must establish full partition coverage
at every pause. Test budgets1/2/split-boundaries, unknown clocks, public/private
routes, correction straddles, conflicts/retractions and strict interval endpoints.
Counts/runtime are explanatory, not performance evidence; no speedup claim.

Before implementation audit API semantics, proof completeness, mutable aliasing,
progress/termination, budget units and exponential worst cases. Record research
intent, defaults, primary/veto/continuation roles and exact failure disposition.
A valid incomplete checkpoint is expected; a missing partition or invalid proof
invalidates the candidate and requires repair. Continue ready independent work.

At most three fresh120second CPU attempts. Save explicit manifests, checkpoints,
full uninterrupted/resumed comparisons, source locks and negative controls. No
probabilities, actual source admission, GPU, agents, installs, fees or publication.
Leave general scalable scheduling, approximate reduction, authenticated durable
storage and tag-induced temporal refinement as separately specified residuals.

## Inspected execution refinement

See data/accounting-master/temporal-frontier-20261027/contract.md.
Pending nodes have reconstructed domains but make no nonemptiness claim. Splits
install every complementary child before pausing. Per-step solver work and the
4096 total cap are distinct. Completion requires no pending node; the independent
checker compares exact source/strict-bound domains and full predecessor trees.

Inspected cap refinement: an explicitly caller-selected execution cap from1 to4096 is separately bound in the checkpoint and independently expected on resume. The request max_nodes stays4096; a smaller execution cap changes only how much work is permitted, never the original temporal question. Test smaller caps to exercise genuine capped states cheaply. Counts/proofs remain exact. The checker also requires a DFS prefix, preventing rearranged completed work after an earlier pending node.
