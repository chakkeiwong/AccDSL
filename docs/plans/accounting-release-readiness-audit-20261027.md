## Evidence contract and skeptical audit

Baseline is the live master snapshot and its exact source/PDF hashes,not the prior
5.32 chat reply. Primary criterion for this audit is a traceable disposition for
every requirement/package and concrete evidence/next action for each release
blocker. Test counts,page counts,build success and populated ledgers are only
diagnostics. They do not establish research completeness,accounting validity,
independent implementability or human comprehension. A source/evidence mismatch
invalidates conclusions relying on it and requires repair; a locally blocked
source does not stop independent review.

Defaults: the design-release interpretation follows the user's manuscript work;
software readiness is evaluated separately. No arbitrary percent-complete score,
publication date,universal benchmark threshold or paid review requirement is
invented. This is a whole-program structural/evidence audit,not a claimed continuous
826-page scholarly read. Inventory every included section and displayed equation;
mark normal-resolution reading and mathematical/source verification only where
actually performed. All other rows stay not_checked or pending. Do not fill a
reading ledger with template passes. The need for a complete sequential regression
can itself be a release finding.

Pre-mortem: a large number of passing finite cases can conceal missing common
interfaces or incompatible scopes; a bibliography can resolve while source
claims remain uninspected; incremental chapters can preserve every word yet leave
contradictions; historical controller acceptance can be mistaken for current
release acceptance. Inspect those connections before recommending more isolated
examples. No method ranking or empirical validity follows from this audit.

Skeptical review passes: release class is explicit without narrowing mission;
current artifacts are frozen; all broad packages and cross-cutting evidence are
covered; unresolved external/human judgments stay separate from unfinished internal
work. Stop when the release-blocker map,critical-path plan,limitations and
readback are complete. The audit does not execute every release repair.
