# Matched authoring for the annual inventory program

25 October 2026. S2–S5; MC11/13/15/23/24/26/28/32/35.

## Question and evidence contract
Can explicit source declarations and typed records compile to exactly the same
AnnualInventoryProgram/1 request, preserving the complete annual book and every
selected inventory premise? Comparator: the frozen annual inventory evaluator
and existing annual source grammar for every old operation. Pass requires exact
lowering, canonical round trips, source hash/span fidelity, pure compilation,
unknown preservation and complete execution-result equality. Frozen bytes,
shape/schema, numeric/date validity, rejected malformed inputs, and wrong digest
checks veto promotion. Source counts and test counts are explanatory only.
No accounting admission, forecast performance or full DSL completion follows.
Preserve implementation, examples, named checks, focused tests, regression logs,
source locks, manifest, replay and decision note in the matching data directory.

## Skeptical audit before implementation
The old parser hardcodes its operation schema and profile, so changing globals
or calling it on transformed source would lose source positions and violate the
frozen boundary. Use an explicit optional profile and a bounded parser using the
same tokenizer/Reader with local schema tables. Delegate all old operation
validation and assembly directly to the frozen authoring module. Keep duplicate
IDs and malformed declarations invalid, while known-false and unknown findings
compile as data and are refused only by execution. Compile must not run the root
or financial transition. Imports are caller-supplied digest-bound data only.
Stage family support separately after this compiler passes.

## Assumptions and defaults
The grammar and portable bounds are reviewed inherited constraints for this
finite profile, not a general-purpose language. The proportional homogeneous
lot model is an explicit user-selected hypothesis from the frozen method. Every
required finding remains declared with provenance. No missing finding is filled
in. The complete unsold annual root comes from the existing checked case; no
stock is fabricated. Exact rational arithmetic is the inherited representation.
Early diagnostics: round-trip a single sale and an old-only program, then verify
the compiled request before checking tax/carry cases and hostile inputs.

## Execution and stop conditions
1. Protect frozen compiler, evaluator, dependencies and examples by hashes.
2. Implement pure typed/text compilation with the optional inventory operation.
3. Check single/split/full sales, residual carry, stale/fresh assessment,
   provenance/unknown/false findings, malformed input, imports and source spans.
4. Run focused deterministic tests and old compiler/evaluator regression suites.
5. Record/replay only after all checks pass; repair concrete failures first.
6. Refresh the master and audit family dispatch as the next dependency.
Stop implementation only for invalid source/semantics, unavailable necessary
root evidence or a material user decision; ordinary candidate failures trigger
repair. Domain/human acceptance remains pending while internal work continues.
CPU-only Python; no random seeds, GPU, network, paid review or forecasting.
