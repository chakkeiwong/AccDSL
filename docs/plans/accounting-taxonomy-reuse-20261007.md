# Source and distribution audit of the real XBRL package

7 October 2026. Direct proposal preparation for E01/E14, MC01/03/30/31/34/35.
Continue C07 of the audited continuation plan. No package installation, product
adapter execution or change to the stopped master controller is included.

The actual Apple FY2024 extension archive is retained, but its ten direct
schema imports and transitive dependencies remain unresolved. The Arelle
source audit already identifies a pinned commit and relevant interfaces. Do
not repeat that audit or treat its Apache licence as permission for taxonomies.

Question: which external source files and distribution conditions does a local,
offline reading of this particular package require, and what must the proposed
adapter report while dependencies remain unresolved? The comparator is the
exact retained archive and its declared import/linkbase/locator references.
Success for this bounded unit is a source-bound dependency frontier, inspected
namespace/target identity for retrieved files, applicable notices, and exact
proposed success/partial/failure exchanges. It does not require or imply closure
of all broader E14 tools or runtime compatibility.

Skeptical audit: the ZIP's six members are not a complete taxonomy. Direct XSD
imports do not enumerate linkbase/locator dependencies, namespaces are not
retrieval URLs, and source download does not validate facts or accounting rules.
Keep each URI as declared, its resolved URL, request receipt, exact hash,
namespace/fragment target and unresolved transitive edge. Do not silently change
an HTTP URI to HTTPS in the evidence; an alternate retrieval route must be
recorded. Inspect retained sources and cache records before new acquisition.
The revised unit passes this audit because success is explicit dependency and
use-boundary evidence, not a successful HTTP count.

Use the existing ten imports as the first acquisition queue. Resolve first-level
references in retrieved XML; expand a maximum of forty distinct external
resources this unit, at most two legitimate routes per resource and 30 seconds
per request. This is an effort bound, not completeness. Preserve every remaining
edge. A successful response must parse as the expected schema/linkbase and match
its declared target namespace or fragment before use. A route failure stops
only that route. Sandbox DNS/network failure must be retried trusted; rejection
or challenge pages are preserved, never bypassed. No accounts or fees.

Defaults: the 2024 namespace is inherited from the actual filing, not the newest
taxonomy; present-day retrieval cannot prove 2024 byte vintage. File hashes pin
this inspection, not a production lock. The declared use is local source
analysis and a proposed optional Arelle adapter; external bundling or release
remains unapproved and requires its own source-specific notices/terms evidence.
Apache code, vendor taxonomies, XBRL specifications and issuer files may have
different conditions. Missing terms leave that distribution decision open.

| Diagnostic | Role |
| --- | --- |
| Wrong namespace, missing target ID, corrupted file or hash mismatch | Continuation veto for dependent use; repair/dispose before claiming support |
| Unresolved import/linkbase/locator or missing terms | Promotion veto for closure or distribution; repair trigger, not a stop on independent work |
| Successful HTTP, XML parse, count of retained files | Explanatory only |
| Complete dependency graph in chosen traversal | Structural source support only; not full validator correctness or accounting validity |

Save receipts, source hashes, graph/frontier, inspected notices and proposed
exchanges under `data/accounting-master/taxonomy-reuse-20261007/`, with a result,
run manifest and supplemental checkpoint. CPU Python/XML tools and curl suffice;
no GPU/framework, stochastic comparison or package installation. Preserve prior
continuation completion, P18/P19, original corpus and frozen controller records.
Pre-mortem: an apparently complete graph could omit a discovery edge or clear
distribution by reading only the main code licence. Record the traversal rules
and inspect source-specific notices before the proposed use decision.
