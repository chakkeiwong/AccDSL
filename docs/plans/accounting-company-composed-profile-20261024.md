# Explicit composed-company authoring and method selection

S3/S4; MC08/10/13/18/24/25/26/28/34. Current references execute a full
retained year, but Python orchestration still decides which steps use the
new return methods and which use retained corporate methods. The next design
must expose that decision as data and validate it before running the year.

Question: can a caller supply one closed typed/text company composition that
binds the source opening, return component, ordered events, selected method
capabilities, annual report and carry without an invisible fallback? Baseline:
the 253-check retained P execution and unchanged six legacy company paths.
The initial executable composition is the retained P case, explicitly named
and source-bound. This is not a claim that all company models are now covered.

Skeptical audit: a generic method string must never load Python; a balanced
imported journal is not an implemented operation; expected outputs must not
become inputs; native and retained routes must have the same legal owner,
currency and before-state. A schema that only embeds a precomputed result
would not answer the question. An imported component's exact retained facts
cannot be silently changed into another company's opening or a forecast.

Design the composition with explicit source and opening identities, component
reference, local caller-trusted capability identifiers, an ordered schedule
whose events reference exact source records and select a capability, a
declared legal annual report, and a conditional next-opening request. No file
path, import name or code is executable from this record. The module registry
is caller-owned and locked. Missing capability or unsupported route fails
before the affected step; unknown findings preserve the completed prefix.

First inspect the exact retained event shapes and existing schema/parser
contracts. Specify structural validation separately from source correspondence
and method availability. Then implement a bounded reference lowering and
executor that calls the checked methods; compare its entire proposal sequence,
annual report and carried state to the recorded predecessor. Typed/text must
match. Test duplicate/reordered/omitted events, wrong source hash or owner,
swapped capability, arbitrary module name, stale opening, extra fields and
attempted report/carry after a partial execution. Preserve legacy bytes.

Default audit: fixed retained source projection is a baseline, not a general
historical admission policy; exact arithmetic and line syntax are inherited
engineering choices; method IDs are explicit capabilities, not standards
endorsements. Counts/timing are explanatory. Primary pass is exact complete
trace identity with explicit route binding and failure semantics. Corrupt
indispensable sources veto continuation; route bugs trigger repair. Pending
human acceptance does not stop authorized provisional design.
