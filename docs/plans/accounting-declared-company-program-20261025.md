## Skeptical/default audit

Do not build another wrapper whose only example is a single payment. The first
program should include ordinary supplied sales and liability payments,an interim
report,direct equity movements if needed,and a subsequent-period operation after
carry. Define all methods in the program's explicit registry and calculate entries
from current state;no imported expected journal or future balance is an input.
Use independent manually derived quantities to detect consistent wrapper errors.

Sequence order is authored explicitly;dates must be nondecreasing within the
current period and carry changes that period. Same-day commands follow their
declared sequence positions. The bounded language is not a general calendar.
A report cutoff later than the last event is an explicit provisional observation
through that date,not proof that no missing events exist. Record that clock advance
in the trace,do not manufacture a transaction,and keep completeness false.

Reports need the current period's actual opening book. After carry,the returned
next_opening becomes the new report basis. Direct equity explanations belong only
to that period. A close command must explicitly supply cutoff,next endpoint,
retained account and all memory policies. Keep historical reports/archives outside
the fixed company memory;never clear prior successful trace on failure.

Before executing,check the full command grammar and static method/schema/type
definitions where possible. State-dependent prerequisites run at their actual
turn. Distinguish invalid program shape from unresolved/refused economic input.
Do not silently resume a failed prefix or accept a changed program as the same run.
Pure replay is enough for this stage;durable recovery remains its own obligation.
