## Skeptical audit and intent

Question: can the checked nested snapshot contract govern the existing finite
term amendment, assessment, collection and carry trace without native financial
builders? The comparator is the retained complete typed requests, transitions
and carry results in receivable-term-history-20261025/evidence.json.

The first call-chain inspection finds a real incompatibility. Existing
OrderedMethodExpansion/1 accepts only scalar fields in a record-map row and
only scalar replace operations. Term claims contain nested term/assessment
maps; assessments insert complete nested records. Replaying stored requests or
wrapping the native state_request builder would not close that gap. Keep the
old expander frozen. Develop the smallest explicit generic nested-record
construction successor before composing the full trace. Native validation
already has declared replacements; precomputed oracle requests remain the
baseline, never the source of candidate runtime decisions.

Research intent: expose exact event eligibility, ordered dynamic record writes,
typed request construction, state checks and carry policy as separate declared
steps. Expected failure: a valid end snapshot can hide a wrongly bound event,
write, historical assessment or cursor. Primary criterion is complete request
and transition/carry equality, plus targeted incorrect-binding refusals.
Source/selection mismatch, drift, mutation, omitted postconditions or silent
partial success veto promotion. Broken comparator/assumptions veto execution
until repaired. Unsupported current construction is a repair trigger, not a
reason to reject the DSL direction. Counts and speed explain scope only.
