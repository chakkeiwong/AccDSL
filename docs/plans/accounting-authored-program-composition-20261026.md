# Compose authored methods with reports and period carry

26 October 2026. MC20/23/24/25/32/33/34; S2/S3/S4.

Question: can a finite authored program reproduce the retained receivable
lifecycle's complete states, journals, reports and carry while selecting
explicit registry identities at each event? Baseline is the original two-chart
lifecycle, including sale, collection, assessments, year-end report/carry and
next-year collection/report. All native engines remain unchanged.

Skeptical audit: an entry can depend on state created by an earlier command.
Therefore validate the whole envelope, all source/method identities and command
syntax first, but validate each registry against its actual current book when
used. Do not use future state to validate an earlier call. A failed later call
must retain the exact successful prefix and remaining commands. Prevalidation
of source identity is not economic eligibility. Preserve the explicit event
projection already recorded by the registry comparison.

The program declares opening book, schemas, mapping, typed memory definition,
hashed registry population and ordered event/report/carry commands. Each event
selects a registry digest and method key. Reports/carry use the original native
request functions; carry policies are explicit per leaf at that point. Typed
memory must remain valid before/after each step. This is a finite reference
program, not a production interpreter or a general scheduling language.

Primary criteria: complete state/journal/flow equality at every event, complete
report/carry equality including notes and memory, and exact native requests
after declared event projection and version dispatch. Verify both charts,
mid-sequence unknown/negative/unsupported cases, duplicate identities, stale
registries, invalid unselected entries, report cutoff, carry policy mismatch,
and tampered results. Demonstrate the supplied authored method variant changes
a program result rather than merely replaying a cached result.

Reference choices: inherit 64 commands and an 8 MiB trace bound as provisional
resource limits; retain direct event dates and explicit policies. No claim of
forecast accuracy, accounting compliance or complete event population follows.
Native mismatch, input corruption, invalid chronology or unbounded output veto
the candidate. Economic refusal is a normal stopped prefix, not a mission stop.

Implement the smallest separate runner using native owners, run focused CPU
comparisons and record the manifest/results. Then integrate the registry/program
group and refresh the full remaining program before selecting the next gap.
