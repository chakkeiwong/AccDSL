# Matched strict authoring for conditional measurement and history families

24 October 2026. S3–S4; MC04/05/08/09/10/11/13/16/24/26/28/35.

Question: can byte/text authors express the same checked conditional families as
the Python record interfaces without losing dates, unknown domains, types,
premises, identities, event ordering or complete parent formulas? The comparator
is each unchanged profile validator/assessor, not a second implementation of the
solver. Cover JointMeasurementConstraints/1, TemporalMeasurementConstraints/1,
ConditionalMonetaryHistory/1, TypedAffineHistory/1 and HistoryMeasurementAttachment/1
in one versioned exchange. A complete typed family is the authoring target;
solver witnesses/results are not accepted as definitions.

Skeptical audit: a generic JSON wrapper alone would not establish a domain grammar
or compatible semantics. Specify declarations for observations, equations,
accounts, memory, templates, events, measurements, state constraints, mappings and
the complete attachment parents. Reuse existing strict token/reader concepts only
where they meet this boundary. No authoring convenience may reorder event arrays,
infer premises, merge observations or silently fill absent required metadata.
Preserve the old validators as the semantic authority and keep attachment support
limited to its existing parent profiles. No typed-history attachment is inferred.

Evidence contract: exact declaration-to-record equality and digest identity,
matched assessor status with independent result replay where supplied, positive
cases across all five profiles, and rejection of duplicate keys/declarations,
unknown fields/profiles, malformed UTF-8, non-finite/floating numbers, wrong
selection hash, missing budgets, after-end content, excessive nesting/size and
mis-typed or reordered economic content. Typed rational values remain reduced
strings; JSON integers are allowed for dimensions and budgets only as validated
by the corresponding contracts. No evaluation, code execution or network fetch.

Default audit: UTF-8 and JSON scalar escaping are explicit transport choices,
not financial assumptions. Bounded line declarations retain ordered collections;
maps preserve keys and semantic identity. Limits reuse the inspected local byte,
node, depth and scalar caps. Version dispatch is closed and explicit; unsupported
profiles reject. All budgets are explicit, including zero budgets. Source facts
and accounting admission remain unresolved according to the unchanged definition.

Pass requires exact typed/text conformance and source locks. Duplicate erasure,
silent defaults, status promotion, dropped parent formulas or altered frozen
evidence veto the candidate and trigger repair. A resource stop or rejected
authoring case is not a global continuation veto. Tests/counts/timing are
engineering diagnostics, not evidence of general independent implementability.

Write the grammar and AST/exchange/error interfaces under
data/accounting-master/conditional-family-authoring-20261024/. Implement
scripts/conditional_family_text_v1.py and focused tests. Record authored source,
exact expected exchange and assessed cases, run scoped regressions and replay,
then refresh controls and integrate typed-state/authoring exposition in a protected
manuscript successor. Keep whole-language acceptance, broader methods and source
admission open; no forecasting, production or paid review.
