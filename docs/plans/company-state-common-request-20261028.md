# Common request with exact native results

28 October 2026. T01; MC08/09/10/13/18/19/20/24/25/28/32.

Question: can a single closed request identify a supported operation while
preserving its native state, result and refusal semantics? Comparator: direct
calls to the existing typed company-path inspector, explicit policy-effect
inspector and CompanyBookReport/1. The latter supplies a genuinely different
native book/query interface and retained PAA report expectations. This is a
common caller for three reviewed capabilities, not a27-profile dispatcher.

Audit: do not infer shared economic state from a common transport. The caller
must pin native implementation bytes, payload identity and any source-byte
resource, retain every native result and distinguish its own refusal from a
native refusal. It must not rerun or normalize a failed financial operation,
repost reports, infer annual completeness from an interim report, or use an
audit result as an actor observation. Existing per-native dependencies and
refusal order remain authoritative after transport validation.

The closed envelope names a capability and operation, input payload/digest,
native implementation digest, resource digests, population scope and explicit
information use. Actor-observation/action requests carry actor identity and
decision/system cutoffs plus evidence references, but remain unsupported by
these three audit capabilities. Malformed actor requests are invalid; well-
formed unsupported requests must explain the missing operator. Joins remain
unsupported. No implicit projection from audit metadata to policy inputs.

Pass criterion: complete direct-call equality for supported valid, invalid,
partial and unknown cases; retained independent report totals and policy
amounts; no source/actor/population/durability upgrades. Return the native
outcome exactly, with any wrapper status clearly a dispatch status. Hard
vetoes: wrong identity, changed input, lost native subresult, altered monetary
output, fabricated history or admitted actor request. Check count and runtime
are explanatory only. No statistical ranking or scientific default change.

Material choices: three capabilities are a conservative scoped implementation
drawn from the reviewed owner map; other owners explicitly remain unsupported.
No code loader or arbitrary callable is accepted. Canonical digest convention
reuses the native sorted-key exact JSON encoding and raw source bytes remain
separate. Supplied populations remain partial/unknown in economic coverage.
No actual-company facts, source vintage or authority is assumed.

Audit verdict: proceed with this bounded caller and accompanying typed
definition; later review must assess T01's original criterion separately from
industry implementation and actual-source obligations. Preserve unsuccessful
attempts; repair harness or implementation defects before another attempt.
