## Question and skeptical audit

Inspect CompanyComposition/1 and SectorCompany/1 before writing another
adapter. They already compute substantive legal/group closes. Their existence
does not establish native compatibility with CompanyOperationPathDraft/1:
Northstar lacks return-right/refund/recovery memory, while the sector report
has a distinct report-only, fixed-context boundary. Comparing totals or
renaming P/B/I as Northstar would be the wrong baseline.

First produce a concrete module contract and capability correspondence using
the retained return-settlement migration as the narrow positive comparator.
Reuse its exact protected source request, state, method and after-state. The
contract must bind legal owner/book/branch, dates, source/view, account map,
read/write state, cash classifications, required findings and unsupported
conditions. Context incompatibility is a refusal, not a conversion. Report
modules cannot post journals; component capital cannot become new company cash.

Then construct a checked caller-side boundary that invokes the existing local
return method on that exact compatible state and compares the whole resulting
state and journal/cash differences with its protected after-state. Test false
owner mapping, missing memory, nonzero unmapped balances, contradictory source
or method identity, unsupported findings and altered shared cash. Show the
current Northstar context is refused with the precise missing capabilities.
Do not claim that this refusal implements a Northstar returns extension.

Primary criterion: exact state-transition correspondence on the retained
compatible return case and refusal without mutation for incompatible joins.
Required semantic result, state allocation, source/method identity and owner
consistency are vetoes. Coverage counts are explanatory only. Changed/missing
indispensable protected bytes halt dependent validation. A candidate failure
triggers repair; a native capability gap triggers the explicit state/schema
extension design, not abandonment or a fabricated successful connection.

Default audit: the return method is a reviewed finite baseline, not the default
accounting policy for all companies; the original profile, source and timing
remain authoritative; exact rationals and fixed caller-supplied code preserve
its existing contract; no external accounting fact, probability, owner change
or tax treatment is supplied by convenience. Earliest diagnostic is matching
the complete retained source and target state before introducing any new hook.

Next specify how native company operation authoring would carry required
module state and explicit eligibility, retain legacy fixtures and partial-year
semantics, and prepare the smallest exact reference extension. Admission of
real source facts, arbitrary corporate/bank/insurance methods, physical
durability and full normalized IR remain separate obligations. No forecasting.

Save design, source locks, exact correspondence and adverse evidence under
