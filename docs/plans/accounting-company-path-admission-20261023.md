## Evidence contract

Question:can the joined path identify every required opening/source/method and
reject provenance/temporal mismatches without relabelling conditional outcomes as
historical facts? Baseline:the frozen v1 opening closure and the164-check path.
Primary criterion:complete reachable closure and bytes verified; every executed
operation binds a versioned local method contract and checked implementation;
path/report/conditional-close records bind to the exact supplied run; adverse
missing refs, changed bytes, mismatched methods and incompatible information
requests reject or remain unresolved. Re-execution matches the stored path.

Vetoes:unknown dependency silently dropped, synthetic dates asserted as actual
issuer availability, contract hash mistaken for semantic proof, wrong method ID,
conditional state passed as admitted Facts, stale result/export splice, path
traversal, or modified frozen package. Repair before accepting the new draft.
Missing required authoritative bytes is a continuation veto for dependent
admission, not a reason to abandon independent design. Checks/count/time are
explanatory. Passing supports local synthetic structural/execution admission;
not a trusted signature, real-book admission, causal forecast, public historical
availability, runtime package loading or independent implementability acceptance.

## Material defaults and diagnostics

UTC date intervals, exact source dates and synthetic-only status come from the
existing portable specification, not convenient new choices. Full dependency
closure is conservative for a combined view; it may block a narrow query that
could later use a smaller justified view. Demonstrate this limitation rather
than filtering the closure silently. Method contracts pin the current source
and tests; code hashes establish identity, not correctness. Conditional closing
keeps all claim/cohort memory and links to its preceding result, never a Facts
reference. Verify each with the smallest positive/negative fixture first.
