# Distinguish new contractual terms from corrected source readings

25 October2026. S2–S4;MC02/05/08/10–13/16/19–22/24–28/30/32–35.
Question: what additional dated state is needed to represent a prospective
receivable-term amendment without rewriting earlier assessment meaning?

Skeptical audit finding: ReceivableSourceContract/1 explicitly reconstructs
separate histories for corrected readings from the same opening; it does not
amend an existing book. The lifecycle control computes historical overdue
consistency using the claim's current due date. A simple replacement of that
date can invalidate a previously correct assessment, or silently reinterpret
it. That is a semantic gap, not a reason to relabel source corrections as
contract amendments or change frozen fixtures.

Inspect current claim type/control, assessment, typed memory operations,
source temporal views and period carry. Construct a minimal discriminator:
claim issued January1, due January31, assessed February1 as overdue20; terms
extended prospectively on February10 to March31. The February1 assessment must
remain interpretable under the old terms, while a February11 assessment uses
the new terms. Cash/principal and all original source readings remain unchanged.
Contrast with a corrected January due date learned on February10: that is a
separate as-of history, not the same contractual event.

Primary criterion is a precise compatible contract and checked counterexample
that distinguishes both meanings. Current-term overwrite, retroactive source
mutation, lost assessment basis or invented accounting treatment veto acceptance.
Amounts, balances and passing schemas alone are explanatory. New consideration,
modification gain/loss, interest/impairment or legal enforceability are outside
this first date-only state contract and must remain explicit prerequisites.

Prefer a separate term-version/assessment-basis record that reuses existing
typed memory and event identity. Do not reset old assessment values merely to
pass the current control. Record whether the minimum repair requires a new
versioned claim type, assessment record or explicit migration. Preserve frozen
engines and release hashes. Implement only after this audit chooses a coherent
boundary. No external legal/accounting claim, source admission, forecasting,
paid review or outreach. Continue internal design work until a real semantic
or input blocker arises.
