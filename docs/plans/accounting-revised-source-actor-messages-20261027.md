# Keep actor messages separate from the supplied financial world

27 October 2026. MC03/04/05/08/10/12/13/18/24/25/26/28/33/34;
W01/02/03/11/12/13/16. Design evidence only; no actual source admission.

Question: what messages can a two-stage rule use when an actor receives revised
financial assertions while the analyst evaluates an explicitly supplied economic
world? Prerequisites: checked joint source selection, whole-world row binding and
original observation maps. The existing world declaration supplies no policy.

Skeptical audit before implementation: distinguish financial assertions visible
to the actor from actual receipt, rights and latent mode. Existing numeric raw
observations include a coupon trigger and a cash-coverage signal; their validity
is a supplied interface assumption. Adding reported receipt as a token is also a
new explicit interface choice, not free access to actual future cash. The same
observation must map identically across worlds, including first-action memory.
An internal source hash or world identifier cannot become an actor message.

Inspect the retained source/observation schemas and define two explicit comparison
declarations: original numeric-observation messages, and those messages paired
with currently selected reported receipt. Both are synthetic choices, neither a
default for an actual manager. Build domains prospectively from original source
heads and declared worlds. Do not select keys only after seeing a favorable
outcome. If the union exceeds 12 keys, retain it as unassessed instead of silently
collapsing tokens or increasing the budget. Broader-domain computation needs its
own reviewed plan.

Primary criteria: first messages depend only on first-stage selected sources and
declared first observation, second keys retain that message and first action,
and all row meanings come from one complete world. A same-head/same-world case
must match the protected policy population. Multiple worlds must share one rule
on equal visible messages; separate world-specific optimal rules do not prove
a common policy. Compare complete candidate sets with the independent oracle,
and preserve pending, unknown and source support. Wrong-world-information,
future-source leakage, lost first-action memory and altered refusal witnesses
are rejection controls. Counts/runtime explanatory; no utility/accuracy ranking.

Before execution record exact declaration schema, expected small counterexamples,
assumption provenance and source locks. At most three 120-second CPU attempts
under data/accounting-master/revised-source-actor-messages-20261027/. GPU hidden.
If the mapping requires a material real-world information choice that cannot be
resolved from evidence, request that fact while continuing independent work.
No agents, actual information claims, fees, outreach, publication or E3.
