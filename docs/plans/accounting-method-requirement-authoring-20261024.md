# Author and exchange reusable method requirements

24 October 2026. S2–S4; MC05/13/15/17/23/24/26/27/31 and G2/G10/G13/G15/G17.
Preserve the verified MethodRequirements/1 reference and Version 3.58. The
selected-condition evaluator is a typed-library baseline. The next comparison
asks whether text authoring and content-identified exchange preserve exactly
the same declarations, dependencies, caller values and assessments.

Skeptical audit: a parser must not add truth or authority, treat a missing field
as a default, accept duplicate JSON keys, silently normalize source text, execute
expressions as Python or turn an imported schema into method eligibility.
No DSL superiority follows from exact round trips. Check the existing frontend
style and reuse appropriate string/record conventions. The current core is
protected by its manifest; build a separate frontend and exchange layer.

Evidence contract: independently authored typed records are the exact comparator.
Primary criteria are typed/text identity, identical semantic assessment through
the existing evaluator, deterministic canonical rendering, immutable manifest
selection and adversarial refusal. Hash changes, dropped declarations or
dependencies, duplicate keys/identities, unbounded nesting or code execution
veto acceptance and trigger repair. Counts and speed are explanatory. No
whole-company/compiler, accounting/source-admission or production claim follows.

Use a small explicit grammar and strict record parsing with no implicit scalar
conversions. Keep rational, boolean, text, date, context and unknown-reason types
intact. Include independently authored known/unknown examples and negative cases;
compare two genuinely distinct method contexts, not only renamed company P.
Assess source-consolidated versus legal-book contexts, and known/unknown caller
findings separately from numerical predicates. Unsupported general source
mapping and full authority adjudication remain residual requirements.

Defaults: a finite line grammar is an inspectable development choice; test
quoted delimiters, Unicode, newlines, duplicates and oversized inputs early.
Canonical output is a transport convention, not a human-usability result.
Three-valued requirement assessment is not family-level logical entailment.
No new numerical semantics or inherited accounting assumptions are introduced.

Steps: specify grammar and exchange identity; implement the separate frontend;
run exact/adversarial/differential checks; record/replay; refresh controls.
Then audit integration of the coherent shared method-requirement design into
the manuscript, preserving mathematical/source content and existing evidence.
Any missing human acceptance limits promotion, not internal drafting.

CPU-only deterministic checks; no external service, GPU, forecast experiment,
background campaign or paid review. Artifacts under
data/accounting-master/method-requirement-authoring-20261024/. Record actual
commands, current commit, inputs, outputs and results. S1–S5 partial; S6 held,
S7 deferred. No global continuation veto is presently supported.
