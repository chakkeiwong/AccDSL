# R06 — Selected native filing readings in portable records

18 October 2026. P16/P17/R06; MC01–06/23–25/27/28/30–35.
Authorised proposal and internal preparation only.

## Question, comparator and skeptical audit

Can the twelve already checked Apple native-filing readings be expressed in
the existing proposed six-field portable Record envelope without conflating
the documentary input packet with original instance bytes, merging repeated
occurrences, losing source structure or inventing financial admission?
The comparator is the frozen native-occurrence-bytes-20261018/readings.json
plus its retained XML slices, and the proposed native-XBRL record definitions.
The synthetic packet schema is not a real-filing input schema. Use the existing
record body types unchanged and bind the frozen documentary packet separately.

Audit passes for this finite correspondence question. A digest-only checker
would not answer it: require field ownership, original spans, independent XML
and exact-value joins, total body-field coverage and semantic corruptions with
rebuilt dependent references. Counts and replay are engineering evidence only.
MarkupText cannot silently become a taxonomy-validated Text: retain the original
tag in the packet and a specific conversion method/caveat. Financial time stays
Unknown even where a source period is clear. No environment-sensitive upstream
operation is required; only standard-library deterministic checks are allowed.

## Evidence contract and research intent

| Role | Requirement |
| --- | --- |
| Main question/mechanism | Finite explicit field translation with immutable source identity, typed references and total provenance mappings |
| Primary pass | Exact six-field envelopes, existing body types, all references closed, all translated body fields mapped to their owning input or named conversion, exact eighteen source spans and twelve candidate values/joins preserved |
| Promotion veto | Wrong source/packet identity, lost unit denominator/dimension, nil-to-zero, numeric scaling, merged repeats, unsupported time/language/admission, incomplete provenance or unchecked type extension |
| Continuation veto | Corruption of protected inputs or inability to reconstruct the selected original bytes; investigate the affected work before continuing it |

| Explanatory diagnostics | Record/mapping/check counts and runtime, with no extraction coverage or performance inference |
| Non-conclusions | Full 1,127-fact translation, generic XML importer, taxonomy validity, Arelle output, runtime compatibility, compliance, source publication availability, accounting admission or program completion |
| Result artifacts | data/accounting-master/native-selected-portable-20261018, with records, field map, conversion specification, checks, manifest, result and additive R08 supplement |

## Defaults and assumptions

| Choice and provenance | Justification/status | Failure mode and early diagnostic |
| --- | --- | --- |
| Twelve facts/four contexts/two units from frozen readings | Existing hazard-based selection; baseline, not representative sample | Accidental new selection: require exact ID sets and source hashes |
| Existing proposed P16/native record bodies and canonical Ref algorithm | Reviewed documentary baseline; remains unregistered | Synthetic input metadata or evidence labels misread as upstream output: separately bind retained-source packet and state authored specification examples |
| Unknown financial context and effective language | Preserve prior candidate-only interpretation; source-root language remains packet evidence | Unwarranted inference: reject concrete financial time, admission or explicit fact language changes |
| MarkupText to portable Text | Explicit representation hypothesis; decoded characters preserved verbatim, original type tag retained by packet mapping | Lost escaped markup/type distinction: specific conversion and byte/text regression |
| Exact rational candidates | Prior fixed source-token readings, no rounding or decimals scaling | Nil/zero/sign/EPS mistakes: independently derive fixed expectations from selected XML |
| Standard-library CPU checks in existing tfgpu Python | Convenience execution environment, no numerical imports | False installed compatibility: record executable/version and no Arelle or GPU execution |

## Ordered work and stop conditions

1. Pin current controls, frozen readers/types, original XML, PDF and R08 inputs.
2. Create additive examples and a precise conversion specification using the
   current Record body types; retain packet and instance BlobRefs separately.
3. Validate types, closures, complete field ownership and exact source joins;
   exercise corruptions that reach the intended semantic checks.
4. Record once, replay read-only, preserve result/manifest, snapshot controls
   and add a uniquely named R08 supplement without rewriting old bindings.
5. Refresh all four live controls, selecting the next independent ready task.

No runtime/controller, installation, empirical campaign, commit, external
publication, outreach or fees. No manuscript rebuild or repeat of completed
3.44 reading. A failed example triggers repair within this unit; it does not
invalidate the research direction. Stop the affected check only for a real
integrity or unsupported-source barrier.
