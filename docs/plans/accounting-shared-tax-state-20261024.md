# Connect conditional current tax to explicit financial state

24 October 2026. S2–S5; MC05/11/13/16/24/26/28/33/35; G2/G4.

## Skeptical audit and evidence contract

Question: can a recomputed conditional loss calculation produce an explicit,
balanced current-tax accrual and separately authorised cash settlement without
changing the protected return/lease engine or inventing annual completion?
Comparator: the unchanged 25-account shared book, original native tax close,
recorded statements, and the checked conditional reconciliation/loss packages.
The old native tax function pays tax immediately, removes deferred balances,
and advances an exclusive tax endpoint beyond the last included state day.
The shared profile rejects extra accounts and that endpoint. Direct reuse is
therefore an untested and likely incompatible hypothesis, not a default.

First capture exact compatibility observations. Then design a protected successor
with an explicitly classified income-tax payable account, an exact native
closing-state anchor, recomputed loss result, separate tax history and accrual
cursor. Keep the original tax-closed cursor unchanged. A conditional accrual
must not clear existing deferred balances or imply financial year rollover.
Do not mutate prior evidence or silently route tax through trade payables.

Primary criterion: exact rational journals, balance-sheet/profit/cash ties,
full input/native result preservation, and negative/tamper cases. Hash changes,
state imbalance, unsupported scope acceptance, loss/result mismatch, duplicate
accrual/payment and overpayment are vetoes requiring repair. Test counts and
page counts are explanatory only. No statutory, company, probability, scientific
forecast, accounting-admission or production-readiness conclusion follows.

## Defaults and implementation boundaries

The first profile is explicitly hypothetical, gross current tax with no credits,
refunds, deferred recognition or automatic payment. Recognition requires an
explicit affirmative assumption. The request names an allocation/cap/expiry
policy through the checked loss result. Accrual timing is the last included day;
coverage uses the exclusive endpoint. Cash settlement requires an explicit
amount/date and sufficient cash. No default settlement amount, FIFO or tax law.

A first bounded successor can anchor to a fresh native period and require zero
existing current-tax expense/payable for that interval. If a limitation is
required, reject unsupported prior postings rather than silently subtracting
an unrelated opening amount. Preserve existing DTA/DTL/deferred expense exactly.
State whether subsequent ordinary native events and financial-year carry are
supported; do not claim them merely because tax operations work.

## Execution and stopping conditions

Write the exact schema and method contract before implementation. Preserve
source locks; start with a positive/zero/loss control and minimal failing
compatibility probe, then boundary and tamper tests. Record every actual command,
environment, wall time and output. Tests are deterministic engineering evidence.
On implementation failure repair and retest; only invalid evidence or a material
unresolved user decision stops progress. Refresh controls after checked work,
then integrate substantive exposition and complete coverage. S1–S5 partial;
S6 held; S7 deferred. No whole requirement closes.
