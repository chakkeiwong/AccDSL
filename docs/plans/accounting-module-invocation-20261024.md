# A common caller must preserve each module's actual capabilities

24 October 2026. S2-S4; MC05/06/11/13/16/17/20/24/26/28;
G2/G4/G13; I01/I03/I04. This is an executable specification reference, not a
production runtime or expansion of the accounting domain.

## Research question and skeptical audit

Can a closed, hash-bound caller interface invoke the existing typed-return and
shared-lease proposals while preserving their different states, exact outputs,
source limitations and refusal behavior? Can the same capability registry prevent
measurement-only and report-only references from being requested as posting
transitions? Baselines are original module calls and the module-composition audit.
Do not replace native arithmetic, merge their openings or rename their owners.

Primary pass: each supported request selects a fixed inspected implementation,
has an explicit capability and exact payload binding, returns the complete
original result, and rejects changed code/schema/request/result or a capability
mismatch. The caller cannot supply a Python path, function or callback. Unknown
membership/findings and native failures retain their original distinctions.
No native result can turn source/accounting admission or durable commit true.

The interface may establish reusable invocation, not general shared-state
composition. A wrapper alone does not prove compatible accounts, owner books,
tax/reporting methods, simultaneous updates or persistence. This distinction is
the main skeptical-plan risk. Keep the broader composition obligations in the
result and select the next repair accordingly.

## Assumptions and checks

| Choice | Provenance/status | Failure mode | Early diagnostic |
| --- | --- | --- | --- |
| Typed return and shared lease | Existing checked original calls; baseline | Re-derive methods or change their context | Exact full native-result comparison |
| Finite trusted local registry | Engineering choice for controlled code selection | Request selects code or unknown capability | Reject unknown module/function/path fields |
| Complete native payload/result | Preservation choice | Common schema drops memory, origins or refusal | Tamper/drop field checks and full replay |
| Diagnostic-only transition proposal | Existing native boundary | Caller labels proposal as durable commit | Reject commit capability; false admission flags |
| One original event per probe | Smallest interface discriminator | Mistaken for full lifecycle conformance | Preserve existing lifecycle evidence separately |

Before implementation protect exact source/metadata and declared schemas. Specify
ModuleInvocation/1 and ModuleResult/1 with deterministic identities, selected
module capability, pinned bundle and payload hashes. Reuse original validators
and trusted APIs, including full raw-hash typed return input binding. Derive no
accounting amounts in the caller. Preserve original after-state, journal, flows,
prerequisites and refusal fields. Apply/commit remain outside this first caller
unless an explicitly audited separate operation is specified.

Test original return and lease positives; altered owner/source hash; unknown
lease membership; failed findings; duplicate event; wrong capability; arbitrary
module/path; forged dropped-memory/cash/result; stale payload digest; and empty
or malformed closed request. Include finite measurement/report capabilities in
the registry with explicit transition refusal. Solver or source issues veto only
affected evidence; unchanged ready work continues. Save complete requests/results,
tests and manifest under data/accounting-master/module-invocation-20261024/.
No new external authority, forecasting, paid review or subagent is required.
