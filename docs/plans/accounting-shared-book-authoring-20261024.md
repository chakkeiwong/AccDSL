# Author the complete mixed book through matched text and typed records

24 October2026. S2-S4; MC05/11/13/16/24/26/28; G2/G4.

## Skeptical plan audit and exact question

Can a finite language state the complete opening and ordered return/lease
events, then reproduce the checked recorded-prefix report without Python
fixture construction? Baseline is RecordedSharedBookStatements/1 with all
saved requests, not a weaker total or newly synthesized accounting example.

Inspected existing frontends: company_program_text.py preserves a fixed
13-event source-bound company program; return_text.py targets a different
return-only schema; conditional_family_text_v1.py provides bounded UTF-8,
duplicate-key rejection, strict JSON values and named declarations. Reuse its
lexical helpers, not its unrelated history-family evaluator. Do not mutate
their frozen grammars or imply that a registry makes arbitrary modules valid.

The new finite grammar has named complete opening declarations, one explicit
account block, return-lot and lease collections, an ordered event block and
an explicit recorded-report request. Exact rational strings, source premises,
false/unknown findings, empty collections and every nonselected memory field
must survive. Missing balances are errors, never zeros. A compiler success
establishes syntax/types only; funding, membership and accounting eligibility
remain the executor's decisions.

## Evidence and assumption contract

Primary pass: text->typed->text round trips preserve complete canonical typed
programs, and text/typed execution both return the complete original report
for the same native request. Schema/type errors carry a declaration line;
duplicate/extra fields, unknown syntax/modules, duplicate account/lot keys,
omitted blocks, stale identity, oversized/deep/invalid Unicode and wrong
scalars fail explicitly. Unknown valid premises compile and remain unresolved
in the native result. Program names and formatting do not change accounting
amounts; source and semantic identity are separately recorded.

Reuse of line syntax with bounded JSON records is an engineering choice, not
proof of ergonomic superiority. It exposes each economic account, module and
event without implementing general expressions, imports, functions or include
paths. Exact original-result comparison is promotion evidence; statement
balance and parser acceptance alone are insufficient. Unexpected semantic
drift, dropped memory or silent defaults veto this frontend. Routine parser
defects trigger focused repair. No external authority or forecast is needed.
