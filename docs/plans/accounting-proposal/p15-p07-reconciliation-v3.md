## Persistence, replay and canonical representation

P07 implements a local SQLite store for the deterministic P05 Northstar fixture. `Store.apply_event` writes the state, journal, measurement, event, dependency edges and receipt in one transaction; initialization similarly commits schema and initial view together. Retained tests inject exceptions at transaction stages and terminate foreground writers before and after commit. They observe rollback or a complete committed cursor. This supports local process-interruption recovery, without establishing filesystem power-loss or distributed-writer guarantees.

The saved execution compares 32 events under uninterrupted and reopened persistence. `check_accounting_p07.execution_evidence` compares the results with direct P05 `Engine` execution and calls the separate journal/statement verifier. The persistent and reopened result hashes agree; the baseline-state hash identifies a different object and must not be compared with a full-result hash. Both execution paths share the same accounting engine. Their equality establishes preservation of this computation, not an independent implementation of its semantics or the accounting validity of its treatments.

The prototype canonicalizer normalizes Unicode string values to NFC, requires unique ASCII dictionary keys, sorts keys and declared set fields, reduces numeric values to rational records, and rejects floating values and duplicate keys/set members. Imported P05 numeric strings remain strings. Tests compare decomposed/composed Unicode, key/dependency order and equivalent rational values; a Fraction survives storage and reopening. These are concrete encoding cases, not a proof of semantic equivalence for arbitrary formulas.

Event identities use owner, schedule version, economic date, phase, operation and occurrence; payload changes under an existing identity are handled as conflicts. Branch identities depend on hypothesis/scenario content. Tests reverse branch enumeration and the P05 dependency schedule. The scheduler rejects ambiguous overlapping same-date events; these tests do not establish arbitrary independent-event commutation. The stream tuple supplies a deterministic hash-derived reference fraction and domain separation; production stochastic execution explicitly returns Unsupported. No assessed generator, coupling distribution or attestation system follows from these checks.

Precise hashes, code/test ranges and retained result pointers will be recorded in the companion claim ledger. The historical evidence is being inspected, not rerun as a new research experiment.

## Corrections, identity and migration

The correction fixture first rejects a 720 extraction from a 120 literal, then records a later disclosure of 110 separately. It binds the accepted reading into a calculation, executes a run, freezes its report, and supersedes the old reading. The new view marks its descendants stale, including state, journal and measurement records; it also rejects descendants introduced after supersession. The original report remains accessible under its old evidence view. These are checked local review transitions and an explicit revenue binding, not general interpretation approval or a full analyst workflow.

Schema 1→2 migration is implemented and demonstrated on an executed legacy fixture. It adds canonical bytes, preserves original payload text and IDs, records mappings, restores immutable triggers, checks foreign keys and replays each run before commit. Failure injection and value-changing transforms roll back; repeated migration reports AlreadyCurrent. Invalid lineage and foreign keys veto migration. This is an equal-decoded-value representation conversion, not a general theorem about semantics-preserving model or accounting-policy changes. A policy change can require a new model/run identity and cannot be disguised as this storage conversion.

## What the proposal still must decide

MC25 still requires portable API arguments/results, typed errors, ownership of evidence, model and run state, and version compatibility across packages and adapters. It must define which edits preserve identity and which create new evidence/model/run identities; distinguish representation-only migration from semantic changes; and specify invalidation, recovery and unavailable-source behavior. SQLite is an explored implementation choice, not a selected product backend. The existence of P07 gives concrete candidate contracts and failure cases that a different backend must account for.

G18 needs one cross-implementation replay specification that includes formatting-only changes, evidence corrections, independent-event reordering, duplicate IDs and branch order. For each case it must say what remains exactly identical, what intentionally changes, which permutations are inadmissible and when a numerical tolerance is justified. Current exact-rational equality has no implied tolerance for a future floating adapter. Portable canonical byte examples, model/package/calendar version compatibility, broader migration cases, non-Z3 adapter exchanges and replay by an independent implementation remain open. Stochastic stream allocation must additionally specify coupling, generator and transform versions and consumption across branches; a reference hash tuple does not discharge those obligations.
