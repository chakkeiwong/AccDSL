## Skeptical audit

The main risks are a stale P17 decision list, treating bounded review as whole
mission acceptance, confusing real-source gaps with the absence of product code,
and repeated checking that produces no deliverable. First save a concrete
assessment, then examine the smallest repairable source/case gap. Use existing
technical source records; preserve unverified authority and historical vintage.
No numerical benchmark, training default, stochastic ranking or GPU run is
proposed. Existing file/document checks are engineering diagnostics.

The unchanged P19 checker is a promotion checker: it intentionally rejects
partial design rows and unresolved blockers. If readiness is negative, preserve
that failure and use a separate integrity diagnostic to verify the negative
assessment's completeness and exact references. Never weaken the checker.

Audit passes for this direct work. New conflicting writer or input corruption
stops dependent work. A source retrieval failure blocks only its unsupported
claim and triggers another legitimate source route or a precise access record.
A negative readiness finding triggers the next specified internal repair;
it does not invalidate the architecture or abandon the research direction.
