## Question, skeptical audit and evidence contract

Can the existing conditional group report retain exact verified legal-book
indirect explanations and explain internal cash removal without treating a
residual as an adjustment? This is a compositional gap between existing profiles,
not permission to invent NCI, goodwill, FX, tax or intragroup-profit methods.
Keep both frozen engines unchanged and add a separate wrapper contract.

For every owner, require a complete DeclaredIndirectCash/2 request and result;
recompute that result and require its retained financial report to equal the
corresponding legal report in GroupPeriodReport/1. Require exact owner population,
context, selected opening/closing, period and cutoff. A valid but unrelated trace
must fail. Preserve every legal report, journal contribution and paired cash
reference; no historical supplied book becomes an executed book by assertion.

Let T be minus the sum of the explicitly removed internal operating flows.
The group bridge is sum over legal books of P+W+N+R, plus T. This follows from
the already checked legal bridges and the group's exact gross cash removal.
The existing group profile permits no profit-changing eliminations, so its
group profit must equal summed legal profit. If that assumption changes, refuse
or use a separately specified successor; do not generalize the identity silently.

Skeptical audit: the old examples have either two operating sides or investing/
financing sides, making T zero. Testing only those examples would miss the new
mechanism. Include asymmetric categories: payer operating/payee financing gives
T=+30; payer investing/payee operating gives T=−30. Both retain group operating
cash20 from the external receipt. These are explicit synthetic interpretations,
not recommended accounting policies. Keep admission/completeness flags false.

Primary criterion: exact legal-program/report linkage, independently calculated
bridge rows, gross pair correction and unchanged group results on the original
four cases. Vetoes: missing or extra owner, mismatched context/cutoff, swapped or
rehashed forged trace, stale flow hash, reused pair, wrong group result, changed
dependency or unsupported profit elimination. Runtime and counts explain the
work only. No statistical ranking, compliance or actual-source claim follows.

## Pre-implementation identity audit

The declared transition engine hashes a cash-flow identity from event ID and
local flow ID. The retained snapshot fixture uses literal flow IDs. Therefore
literal equality with that old fixture would be the wrong baseline. Preserve
the old fixture, record an explicit one-to-one flow-ID translation and compare
every other flow field and the complete opening/closing books after only that
translation. Update pair references and their hashes by the same mapping.
The snapshot-derived report then must equal the executed report exactly. This
tests state generation and semantic equality without claiming old provenance
identities are byte-identical. No broader normalization is permitted.

The trace registry also needs an empty input schema for a no-op memory method.
The old snapshot registry contains only its state schema. Add this one explicit
schema to the comparison requests; preserve all original schemas and state.
Report request hashes necessarily differ because they bind that registry. The
comparison records both requests, this schema addition and the flow-ID mapping,
then requires exact full reports after those declared adapter changes. It must
not ignore any result field or use an unrestricted normalization.
