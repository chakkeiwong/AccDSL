## Question and skeptical audit

Which method boundaries are actually reusable across the existing company,
return, lease and sector references, and what prevents safe composition within
one company? The last increments showed that actual issuer measurements do not
supply executable state. Repeating another synthetic lease case would not answer
the separate language/module question. Inspect the retained code, contracts and
tests before designing the next shared interface.

Baseline: the original company-module boundary and CompanyComposition migration,
native return execution, SharedLeaseBook/1, existing method requirements/effects,
and report-only SectorCompany. Use their actual current IDs, supported context,
source locks, state requirements, account footprints, memory and outputs. Never
rename owners, currencies or authority scopes to create a convenient join.
An old negative Northstar return finding may be superseded by later native
return work; preserve its historical scope and inspect the newer code.

Primary pass: a source-anchored capability and compatibility inventory, with
precise distinctions between measurement-only, proposal/posting, report-only and
durable commit behavior; identify one remaining reusable-boundary repair with
an existing comparator and concrete adverse cases. Working syntax, balanced
journals or successful individual examples cannot promote general substitution.

Veto findings: added opening cash/equity counted twice, incompatible legal books,
lost gross cash origin, dropped memory, falsely merged context or admission,
report-only code treated as a posting engine, or persistence claimed from pure
proposal functions. These veto a proposed composition, not the research plan.
Repair trigger: stale contract or capability statement. Continuation veto:
corrupted comparator or absent essential source that prevents a faithful audit.
Do not stop for a missing later sector engine if an independent shared boundary
can be specified accurately.

## Default audit and bounded execution

The named references are baselines because their behavior is retained and
testable; they are not universal method defaults. Start with file/entry-point
discovery and selected definitions. Record full hashes, exact supported functions
and the original scopes before running a small regression or adversarial probe.
No more than one finite composition diagnostic per unresolved distinction is
needed initially. Unit tests establish engineering behavior only; no empirical,
accounting, valuation or forecast superiority follows.

Deliverables under data/accounting-master/module-composition-audit-20261024/:
protected source lock; capability inventory; compatibility/admission findings;
focused diagnostic if needed; result decision table and a concrete successor
plan. Keep actual issuer state missing where it is missing, and link the Henkel
source-to-state dependencies without importing EUR measurements into synthetic
USD books. Update active controls after the audited result. No subagents,
professional engagement, publication or production promotion is required.
