# Bind retained sector assessments to their actual records

25 October 2026. S2–S4; MC04/06/11/19–22/24–28/30/32–35.

Question: can a company-world component resolve its exact retained sector
state, source conditions and information view without gaining a posting
capability that its native method does not have? Baseline: CompanyWorld/1
checks opaque handles only. Compare against the frozen BankAssessment/1
capital.final request and InsuranceAssessment/1 route.full request and their
complete typed dependency closures and blob bytes.

Skeptical pre-run audit: native Profile records explicitly say accounting_effect
is none. The insurance AccountingHead contains a balances digest, not the
balances themselves. The bank context uses USD million, supplied US GAAP/CECL
and a Solo perimeter; the insurer uses USD illustrative_million and historical
EU IFRS17 authority. A common currency does not establish compatible units,
accounting bases, dates or an actual group. The corporate packet is a group
State, not a legal-book state; this adapter must refuse it pending explicit
projection. These findings determine the scope, not a later qualification.

Implement a read-only binding of these two named cases to one selected legal
book. Hash-check native packets and schemas against retained manifests; verify
the selected record closure using its original schema and portable record
identity. Resolve every declared blob in that closure to exact local bytes.
Bind owner/entity, book, currency, state, source root and view to the native
case. Preserve native units, basis/perimeter, dates, unresolved duties and the
whole unchanged company world. The bank source root is its RulePackage (ten
SourceSupport records), not a single arbitrarily chosen source. No native
calculation is rerun or promoted by this reference operation.

Primary criterion: exact native record/body/byte preservation and immutable,
correctly distinguished refusals for a changed owner, source, view, profile,
missing record, wrong schema, changed blob or unsupported case. Native bank
and insurer records are separate comparators; do not compare their numbers.
Promotion veto: any mismatched/missing dependency or unnoticed context change.
Repair trigger: local mapping or test error. Continuation veto: unavailable
required native evidence until recovered; independent ready work continues.
Counts and hash matches establish identity only. No accounting admission,
current-law determination, consolidation, valuation calibration, complete
insurance ledger, actual method execution or predictive ranking is concluded.

The two fixed cases are a scope choice drawn from retained evidence, not a
representative sample. JSON-schema validation uses the installed library and
local frozen schemas; it is an engineering check, not an accounting proof.
Input limits bound this finite resolver, not the financial model. Reject
unknown profile/case combinations early. Store exact results, dependency locks,
manifest and read-only replay in `sector-reference-binding-20261025`.

After the boundary passes, integrate its substantive constraints and examples
into one manuscript successor, refresh the complete 53/6/46 coverage, and
return to explicit bank/insurance state and method bridges. Populated
source-backed invoices and full company-statement cases remain dependencies.
