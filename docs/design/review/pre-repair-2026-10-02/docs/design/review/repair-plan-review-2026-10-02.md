# Skeptical review of the repair plan

Date: 2 October 2026. Review by the executing author, before substantive repair.
Plan: `docs/plans/accounting-gap-repair-2026-10-02.md`.

| Challenge | Finding and correction incorporated in the plan |
| --- | --- |
| Wrong baseline / stale context | The recovered PDF is a 60-page incomplete design, not a nearly finished engine. Preserve it and the MC register; evaluate against G1–G18, not merely successful compilation. |
| Proxy evidence | More pages, rows, sources or passing arithmetic cannot establish implementation completeness. Require complete input-to-result cases and explicit specification/implementation/domain-review statuses. |
| Scope shrinkage | A tiny loan example would omit the user's corporate/sector mission. Add the complete company plus bank, insurance, hybrid, consolidation and cross-standard cases; retain later method obligations visibly. |
| Hidden synthetic assumptions | Exact totals and annual cash settlement can conceal ordinary disclosure difficulty. Add rounded totals, working capital, a revised interim view and real filing context; record simplifications as assumptions. |
| Solver mismatch | Unknown principal times unknown fraction is bilinear. Use fixed/floating amounts and derive conditions for equivalence; unsupported fragments must not return infeasible. |
| False real-case completeness | Copying a few real figures cannot close whole-report coverage. Inventory the entire chosen package and cross-references, with explicit unformalised sections; model only declared supported movements. |
| Unfair DSL comparison | Comparing a typed DSL against an unchecked spreadsheet predetermines the answer. Compare text and typed-library authoring of the same IR, with the same checks, cases and user tasks; claim no usability winner yet. |
| Research labels mistaken for reading | The generator's generic exclusions are not individual relevance review. Separate candidate discovery, metadata screening, full-text inspection and adopted technical support. Missing decisions fail generation. |
| Unsupported standards | Overview pages cannot establish posting rules. Obtain paragraph-level support for selected examples; use explicitly illustrative contracts elsewhere and keep specialist review pending. |
| Missing stop/repair conditions | Timeouts, retrieval blocks and unsupported branches need different treatment. Keep unknown branches and probability mass; isolate source blockers; continue other authorised units. |
| Environment mismatch | No usable Git and no research MCP were exposed. Use content snapshots, local PDF utilities and official source retrieval; no GPU, training stack or global-policy changes. |
| Uninformative commands | Broad builds cannot check semantic targets. Small deterministic checkers will independently sum journals, solve bounded reference constraints and test time/identity/cross-reference counterexamples before rebuilding. |
| Narrative degradation | Appending an inventory would produce another specification dump. Introduce methods through the complete company, retain existing derivations, and inspect both prose and rendered pages after integration. |
| False finality | A self-review cannot certify a human voice, accounting compliance or empirical forecasts. Keep those statuses pending and report remaining evidence separately from completed repairs. |

Decision: execute the corrected plan. No material unexamined implementation
default is treated as validated: reference rates, tax rule, company model,
resolution, workload limits and solver fragment are declared teaching/design
choices with corresponding counterexamples. No scientific ranking or default
forecast policy will be promoted by these deterministic checks.
