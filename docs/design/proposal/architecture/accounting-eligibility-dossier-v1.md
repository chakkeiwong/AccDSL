## Question, evidence and stopping rule

The primary criterion is a paragraph-anchored precondition table and eight
assessment examples that distinguish missing evidence, a disproved recognition
condition and a method outside the proposed scope. The comparator is a screen
using the same category label and balanced candidate journal on the same eight
fact packets. It is deliberately a limited screen, not a competing accounting
system. Arithmetic explains journal consistency; it cannot promote eligibility.
Missing source support, treating unknown as false, changing accepted replay
ordering or changing predecessor evidence veto this bounded result. A source
version outside its retained window limits this method; it does not prove that
an instrument can never be recognised.

Skeptical audit before drafting: the compared inputs are matched; inherited
facts and authority scope are explicit; no implementation, stochastic experiment,
new dependency or performance comparison is proposed. The deliverables answer
the precondition question, not the lifecycle question. Stop after the dossier,
eight assessment specifications, finite calculations and registered structural
check. After independent review, integrate the preconditions into versioned
request/assessment records. Plan lifecycle expansion separately.

## Proposed decision inputs and outcomes

Every condition carries a value or unknown reason, provenance (source rule,
transaction evidence or explicit assumption), scope and version. A historical
assessment needs supported transaction evidence; synthetic assumptions can only
produce **conditional synthetic eligibility**. The source citation supports the
rule, not the truth of the transaction facts. The fixture packets expand their
complete input sets; case IDs are local document labels, not request identities.

| C02 instrument | Holder's asset, instrument terms, scope exceptions and transfer conditions | Unknown → unresolved; excluded instrument or unresolved cross-standard method → outside_scope |

Stipulated rationale remains conditional, not established classification |

Evaluate all conditions and retain every finding. Proposed summary precedence
is `ineligible` (a disproved recognition prerequisite), then `outside_scope`
(known authority/method limitation), then `unresolved` (missing facts), then
`eligible`. It is a local reporting convention, not an accounting rule; a summary
must never erase lower-precedence findings. C09's branch is a three-valued OR:
one supported qualifying route suffices even if the other is unknown. With an
unknown branch, C10 reports a pending method decision, not a known supported
method. A conditional `eligible` result cannot authorise a historical posting.

No assessment example commits anything. Noneligible assessments have no journal
proposal or state delta. The conditional control names a candidate journal for
explanation only. For all eight examples, posted journals, account state, event
identity map and committed receipts remain unchanged; there is no fabricated
receipt or reusable canonical request reference.

Accepted request processing remains: validate structure/reference bindings;
look up stable identity; return an existing matching committed receipt or
conflict; only for a fresh request check state freshness and assess eligibility.
Replay retrieval is not renewed eligibility. A later version must bind the
dossier/method version, authority edition, transaction facts and their
evidence/assumption versions into immutable request dependencies. Changing those
for the same identity cannot silently reclassify a committed event. This document
does not modify the accepted record schema or create those bindings.

## Comparison and remaining work

The limited comparator receives a constructed balanced candidate journal even
on cases where this dossier forbids a proposal. That journal is a diagnostic
input, not authorised accounting output. The category-and-balance screen lacks
contractual, temporal, authority, fee and valuation evidence and therefore cannot
decide those conditions. Both equal-price and unequal-price examples remain
conditional design examples; no technology or scientific ranking is asserted.

The proposed internal answer is to require explicit preconditions and retain
unknowns. The competing interpretation is that an upstream FVTPL label already
encapsulates the judgments. It can do so only if its immutable assessment includes
the facts, applicable authority, reasoning and review scope; the existing label
alone does not. The consequence is additional evidence requirements, not a new
accounting conclusion for A01 or A03. This preparation continues internally under
MC35; no paid engagement or outreach is requested.
