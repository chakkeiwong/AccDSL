\subsection{Reading an explicitly adopted profile}
\label{sec:adopted-profile-effects}

A corrected request index is useful only if the next interface understands
which policy produced it. The original common reader expects the old insurer
world and its slash key. Removing the new policy reference to satisfy that
reader would hide a relevant execution condition. The exact-time bank profile
presents a different issue: its request and result schemas change, while its
submission schema remains the original one. A shared schema prefix cannot
describe that deliberately mixed set of versions.

\code{PublicationEffects/2} retains the existing financial-effect meanings and
adds an explicit execution binding. A provider names the exact financial
profile, each record kind's schema, the identity policy when one applies, and
the checked source packet and selected exchange. It invokes the corresponding
native validity checks before describing the effects. The insurer provider
preserves the policy reference in both worlds and uses the ordered pair key.
The bank provider preserves its exact-time rules and the original submission
schema. Neither infers financial commitment from the Boolean alone.

Source identity also matters within a packet. Several insurer recovery examples
have the same display label. Selecting them through a map keyed only by that
label would silently discard earlier examples. The provider therefore uses the
exact packet hash and a stable position-qualified identifier, while retaining
the original label for explanation. This distinguishes every retained example
without changing its request, receipt or financial state.

The composition language keeps its existing declarations and adds one explicit
dependency check. Equal financial profiles with different execution policies
require a policy adapter before their complete worlds can form a sequence.
Financial identity still belongs to the financial profile and request pair:
changing the policy does not create a second namespace in which the same
payment may be posted again. Different financial profiles retain their separate
state-adapter requirement. An unknown acknowledgement continues to make every
dependent stage unresolved, including stages whose adjacent worlds happen to
match.

The checked successor retains all 77 earlier complete text/typed composition
results. Its 959 effect descriptions cover 672 retained insurer exchanges,
14 new exchanges, 168 unknown transport observations and 105 descriptions from
63 exact-bank packages. Ninety-one further compositions include the native
insurer commit-to-report chains, bank publication/replay pairs and explicit
incompatible, partial, refused and unknown cases. All saved descriptions and
assessments recompute through fresh readers. A wrong policy, hidden head change,
duplicate posting on replay or invented uniform bank schema is refused.

These comparisons preserve checked protocol meanings across the named
providers. They remain conditional on the native financial evaluators and
supplied facts; they do not supply a universal dispatcher or the missing
insurer-to-assessment state conversion. The exact source changes, complete
descriptions and dependency cases are retained under
\path{data/accounting-master/adopted-profile-effects-20261026/}.
