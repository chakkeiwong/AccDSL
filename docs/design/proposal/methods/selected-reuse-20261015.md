# Selected first adapter and its unresolved runtime admission

The first optional importer is a source-preserving native-XBRL adapter over the
retained Arelle commit 01f6a4656c2c6551d2f05f31c9d74366d133ee7e. This is a
documentary selection for an initial implementation slice. It does not assert
that the commit is a released package, recommend the newest version, or select
every plugin. The concrete input is the retained Apple 2024 native instance and
its recorded taxonomy graph. Its 27 resources and 3,551 recorded reference edges
are a static source map, not successful XML/XBRL validation or full disclosure
closure. Financial notes and untagged content retain their own inventory.

Selection follows the mission's preservation need: native facts carry contexts,
units and occurrence relationships that a flattened table cannot reconstruct.
The exact earlier API, inline-value and fact-identity inspections remain the
technical support. Use one session in its owning thread per process. Request
validation and validationExitCode, disable formula execution, automatic plugins
and additional packages, copy required records while the model remains open,
then close it. Process isolation may support later parallelism, but no throughput
claim follows. Retain logs and model errors as well as the controller Boolean.

The PDF baseline is the retained pdfplumber commit
4c64b92d5caccd71c645e98e0fabb0c4dba7ff45, selected for explicit character/page
geometry on machine-generated PDFs. It remains a development comparator; its
README does not prove that any filing is parsed correctly. Source pages and
manual located evidence remain available when a converter fails. A scanned
page without admitted OCR is explicitly unresolved. The fallback never converts
unrecognized content to zero or counts it as processed successfully.

Docling and its TableFormer/OCR paths remain alternative candidates for separate
evaluation. The inspected Docling commit eda5b5fc86d10b2b79a900ff3e69fc159d5f6014
declares docling-slim 2.133.0, and the inspected docling-core commit
d7cef4c10a7574c02ba9ea1b02c9c494dfe8b0df declares 2.99.0. Those two source
identities do not solve the dependency graph. No generic standard/all extras are
selected. TableFormer 4.0.2's inspected greedy decoding, bbox dependencies and
OpenCV provider obligation remain source-specific findings. EasyOCR weight
identity and applicable model terms remain unresolved. An arbitrary Torch/
torchvision pair would not resolve those facts. None of these model paths is
silently used when the first importer cannot handle a document.

## What is pinned and what remains to be resolved

The source-selection manifest pins every retained body used by this decision,
the exact Arelle dependency declarations and runtime options, the Apple URI-to-
bytes map, earlier field-preservation cases and known terms dispositions. Its
status is documentary_source_selection, not environment_lock. Required base
dependency ranges and build requirements remain ranges. Before execution, a
separate immutable environment record must name the operating system/architecture,
Python build, wheel/sdist source, exact direct and transitive versions and hashes,
build tools where relevant, enabled extras/plugins, notices and installed import
paths. The record must pass a resolver and compatibility review for the actual
platform. A changed dependency, transform registry, taxonomy, model or config
creates a new identity and invalidates dependent admission. The source selection
does not freeze an untested environment as a project requirement.

All network resolution is disabled in the proposed runtime. A URI is admitted
only if its retained bytes and full hash match the request's map. A missing file,
changed body, wrong namespace or absent required fragment returns a named
unresolved dependency before affected values become proposed financial facts.
A stale cache pathname is not evidence that bytes exist. The original schemas
remain unchanged; an external resolver supplies the mapping. An isolated cache
may contain only the same admitted bytes. No current or later taxonomy is a
silent substitute for the historical package.

Terms are tracked by subject and intended use. Retained Arelle code notices are
distinct from dependencies, XBRL definitions, FASB taxonomies, issuer files and
model weights. The historical taxonomy dossier's unversioned retrieved FASB
page shows 2027; it does not establish terms for the 2024 package. The missing
component-specific XBRL Software Notice remains an exact source dependency.
This proposal neither distributes the resources nor reaches a blanket legal
conclusion. No lawyer or vendor is contacted. Continue feasible source and
dependency preparation before referring a specific unresolved application.

## Documentary exchange and failure boundary

The closed DocumentaryAdapterExchange/1 fixture envelope is a verification
record for this proposal; it does not modify the product's I1 schema. It includes
the request identifier, source-selection identity, local resource bodies/hashes,
required URI closure, admitted transform identifier, complete lexical contexts
and units, occurrence references, expected proposed/unresolved status and
diagnostics. Every referenced fixture body is supplied. Expected outcomes are
authored specification examples, never represented as Arelle/Docling output.

The first synthetic case has raw 1,234, admitted comma grouping and scale −3.
The proposed value is 1.234, with the lexical token, scale, unit, context and
occurrence retained. The declared precision is metadata, not a second scale.
A nil occurrence remains a separate unknown even when another occurrence has
the same concept. Two equal amounts with different contexts remain distinct.
Unknown transformations, absent contexts or typed dimensions and changed
resource bytes yield unresolved affected records. They cannot be repaired by
guessing from a nearby amount. A partial run retains completed proposed records,
the unprocessed frontier and diagnostics; it cannot claim package completion.

Replay of the same request identity and exact bytes returns the same proposal
receipt; the same identity with changed bytes is a conflict. Cancellation before
completion publishes only the declared partial proposal and unresolved frontier.
No review acceptance, journal authorization, accounting commit or successful
runtime validation is generated by these fixtures. Later product integration
must translate the envelope into existing evidence/review requests and test
that translation against the full portable schemas. Passing documentary field
and arithmetic checks cannot establish that runtime translation.
